## 先学外部：OpenAI 的 Intelligent UI（2026-10-07/08 随 GPT-6 推送）

三条与本项目直接同构的设计事实：

1. **不是生成代码，是生成一种受限的界面语言。** 模型不写 HTML/JS，它吐一种自定义的 UI 语言，
   服务端编译，客户端在沙箱运行时里用约 70 个原生组件渲染。这和本仓库"模型只能交 markup，不能交
   代码；3D 是声明式图元表；`guard` 是白名单门"是同一条决定 —— 差别在于 OpenAI 把编译放在服务端，
   而这里编译（解释）在浏览器，因为"没有后端网关"是这个产品的前提。
2. **界面随生成逐步呈现，不等整段答案写完。** 原生可流式组件库 + 编译器，边生成边上屏。
   本仓库早就在这一头：`paint` 逐笔长在舞台上、`clock 不许跑在画面前面`（第二条时间规则）。
   Intelligent UI 值得学的不是"能流式"，而是**它把"什么时候该给界面、什么时候该给文本"当成
   模型训练目标**（清晰度/有用性/完整性三问），并把这条判断交给模型而不是交给 UI 分支代码。
3. **交互不再额外调模型。** 用户点了按钮、拖了滑杆，不再走一次 AI 调用 —— 界面自带状态。
   本仓库现在是**反过来的**：`ask_learner` 的答案落回带子（`answer` op），学习者点一下节拍条就剪带
   重排。这一条我判断**不该照抄**：这里的每次交互都是课的一部分，得留在带上；但 OpenAI 那句
   "交互不付费"戳中了另一件事 —— **本仓库的交互确实付费，而且付费的是观众那一头的整卷重排**，
   不是模型。这就是下面的两件。

对照之后剩下的判断：Intelligent UI 的方向是"回答即界面"，而 Cue Studio 从第一天就是
"回答即演出"。所以不该往这个仓库里加"生成式 UI 组件库"，该做的是把它那句工程承诺兑现到底：
**界面跟着内容长，而且长一截只付一截的钱。** 前者已经做了（三处续排），后者还没做完 —— 就差观众
那一头。

| 带子 | 一帧落在同一拍内 | 一帧跨进下一拍 | 跨拍时节拍条收起 | 节拍条单独挂 |
| --- | --- | --- | --- | --- |
| 600 拍 | 1.57ms | 6.4ms | 1.79ms | 11.6ms |

`⟲ 一拍`、以及每 2.5 秒一次的正常走钟都会跨拍 —— 一节课走到底要跨几百次。

## 候选方案

C. **（本件第一件）`logRows` 的整卷重排。** 就是上一份 plan 里那件 C，前提仍然成立：`describe`
   读只有自己那一笔的 `op` 字段，加上 `gates.get(o.gate)` 那张卡里**前面那一刀**落下的 `op.prompt`；
   被身后那一笔回头填的 `gate.said` 一个字也没印。所以它是**纯尾巴**，和 `TapeIndex` 同形、比
   `StandingIndex` 简单。
   改法照搬仓库已经立好的门形：`RowIndex` + `rerows(ix, compiled, tape)`，认的是**两张容器的引用**
   （`stage.log.tape` 与 `compiled.gates`）—— `append` 让带子长一截（引用不变 → 只排新落的那一截），
   剪带、载入、清空换数组（→ 整卷重排，那是诚实的价钱）。`Compiled` 那份记录每批都是新对象，所以
   `useMemo` 的依赖换成两张容器才是对的；这就是"引用抖动"四个字的正面解法。
   一处必须防的修过头：`RowIndex` 得挂在**带子**上而不是挂在组件里（`WeakMap<tape, RowIndex>`），
   否则"认引用"这一问在 React 那一头根本没有答案 —— 组件重挂、tab 来回切都该复用同一本账，
   而换带子必须换账。
   护栏按计划里那句立：`gate.said` 是一颗正被回头改的字段，今天不印不等于明天不印 —— 所以
   `rows.test.ts` 钉"印一个会被身后那一笔回填的字段，这一层的缓存必须红"（拿变异跑，记在下面）。

D. **（本件第二件）节拍条跨拍那一帧。** 同一句话的另一半：`Segs` 每跨一拍就把整条节拍条的
   段**重做一遍元素**，React 拿到的是全新引用，于是每一段都重新 render。改法还是那句
   "已经排好的那一截不许每批再排一遍"，只是这里长的不是尾巴而是**头上与身上各一格**
   （丢亮的旧 `now`、拿亮的新 `now`）：段元素按**落下次序**记住，跨拍那一帧只重做那两段。
   前提是把"这一段的宽度"从 `total` 上摘下来 —— 现在 `width: max(46px, share%)` 里的 `share`
   分母是整场长度，于是**落一笔也得整条重做**；换成 `flexGrow = 自己的毫秒数`，宽度由浏览器
   按比例分，段与段之比正是时长之比，`total` 一个字也不进 props。这是本件唯一一处**改观感**的地方，
   所以它得单独钉（比例、下限 46px、溢出仍然可横滚）。
   `armed`（哪一段被点准备重排）本来就在尾巴之外，跟着 `now` 同一句处理：只重做那两段。

C 与 D 分两次提交：它们的门形相同（认容器引用、只重做变过的那几格），可 C 的错法在"什么算变过的
一行"（答案行读前面那一刀的卡），D 的错法在"什么算变过的一段"（`now` 会**同时**动两格，
而 `total` 一动就是全条）。钉的东西不同，所以各走一遍仓库的三层。

## C 已经做完（这一节的实测与两处改判）

落地的是 `src/ui/rows.tsx`（`RowIndex` + `rowsFor(compiled, tape)` + `rowsMeter`）、`OpLog.tape`
那一个 getter、`App.tsx` 那个 memo，测试是 `src/ui/rows.test.ts` 13 条，记在 README
"已经排好的那一行不许每批再排一遍"那一节。两处和这份方案写的不一样，都得改在方案里：

1. **"交出去的是同一个数组对象"那句是错的。** 这一件原本打算直接交 `rows` 本身（引用不变 → React
   逐棵子树跳过）。实测：那些行是那个 div 的多个 child 之一，React 给它一个 fragment 节点，浅比对
   问的就是这个数组本身的引用 —— 引用没换就整串当没变，新落的那一行**永远进不去 DOM**（带子 51 格、
   DOM 里 50 行）。改成 `view()`：没动过交同一个引用，动过重新抄一份。留下的那笔"每批一次 O(带子)
   的指针抄"记进 `rowsMeter.published`，是消不掉的，除非给日志面板一个自己的订阅。
   探针第一版拿"数组是唯一的 child"试，那一头两种写法都进得去 —— 又是一次"探针得先证明自己量得到东西"。
2. **C 的依赖多了一处不是纯尾巴的东西**：`restore` 按号排，所以"答在问之前"是一卷合法的带子，那一行
   要等它的题卡进账才印得出题面。旧写法每批拿整张卡表重排整卷，隐式地付了这个答案；续排必须由知道
   改动的那一方（卡进账这一刻）回头补那一格。这一处是 `Waiting` 那张表，形状和 `StandingIndex` 的
   `touched` 流水一样，只是等的东西少到可以直接记下来。
3. `grow` 里"先收卡后排行"那个次序**不是语义**、是价钱：反过来那一行会先落进 `waiting`、同一趟
   `grow` 的收卡那一环当场补回来，答案对、多付一遍工（变异跑过：形状那两条全绿）。

都会碰到，一节课走到底要跨几百次。下面 D 的设计要点照旧，只补一句：`Segs` 那一头的浅比对问的也是
`beats.map(...)` 那个新数组的引用，所以 D 不能只靠 `memo` —— 它同样需要一个"记住段元素、只在变了
时换引用"的容器，和 C 是同一句话。

## C 的设计要点

1. `describe` 搬进 `src/ui/rows.tsx`，成为 `describeOp`；`RowIndex` 手上留三样：那张
   `readonly OpEntry[]`（带子本身）、`compiled.gates` 的引用、一个 `gateBySeq`（**只在吸收尾巴时
   长**的查表，不是每批拿整张卡表现建一遍 `Map` —— 那本身就是整卷的钱）。
2. 门与 `reindex` / `restand` 同形：`rerows(ix, compiled, tape)`。`holds` 两张都比（`tape` 与
   `gates`），只认 `tape` 的写法能把新落的那些行接到一本换了卡表的账上 —— 那一头 `answer` 行
   指不到它的题卡，红护栏里"只换卡表必须整卷重排"那一条。
3. 行元素按带子次序存在一个数组里，`absorb` 只往尾巴 push。返回的是**同一个数组对象**：React
   每帧比对整棵树时，未动的行引用不变就逐棵子树跳过 —— 这正是 C 要换来的那件事，也是
   `view.test.ts` 那件旧修改已经在用的那条规矩（"记住的必须是元素本身，不是每行的文字"）。
4. 三层：
   - **形状**：随机带子逐批追加，每批落下之后拿续排的 `rows` 和"拿这一批为止的带子整卷重排一遍"
     逐行对账（文本与 key）。参照不许复用缓存。
   - **价钱**：不量毫秒，数**这一层做了几次元素**（模块导出的计数器）。落一批只许做本批那几行；
     时钟走一帧一次也不许做；带子换卷那一条付整卷（诚实的价钱，钉住它不许偷偷变成常数）。
   - **护栏**：一次建完与逐批续排同解；内容相同换了数组必须重排；只换卡表必须重排；
     `answer` 行仍然认得题卡（`view.test.ts` 那条旧断言搬进来）；`said` 回填不许改已经排好的行。

## D 的设计要点

1. 段元素记在 `SegIndex` 上，认 `compiled.beats` 的引用（`beats` 是会长大的容器，和
   `cues`/`gates`/`props` 同一批）。跨拍不动 `beats`，所以尾巴之外只重做两格。
2. `now` 与 `armed` **不进 props**：它们是"哪一格"的事实，不是"这一格长什么样"的事实 ——
   改成缓存里那两格重做（旧 `now` 那一格去掉亮、新 `now` 那一格加上亮）。这样跨拍那一帧做的
   元素数 = 2，与带子多长无关。
3. 宽度换成 `flexGrow`，于是 `total` 从整条链上消失；`Seg` 的 props 只剩 `stage`/`teacher`/`b`/`i`/
   `now`/`armed`/`onArm` 里的 `b`/`i`/`now`/`armed` 四项，其中只有变过的那两格换引用。
4. 价钱那一层仍然数**重画次数**（`teacher.canReroll` 的调用次数就是段被重画的指纹，
   `view.test.ts` 早就在用）：跨拍那一帧至多两次；带子长一截只许新落的那几拍；
   走一帧不跨拍一次也不许。

## D 已经做完（这一节的实测与三处改判）

落地的是 `src/ui/segs.tsx`（`SegIndex` + `segsFor(compiled, view, now, armedSeq)` + `railMeter`
三格计数器）、`src/ui/Seg.tsx`（拆出来的段组件，仓库那条 `react/only-export-components` 逼的）、
`src/ui/BeatRail.tsx`（那个 memo 容器 `Beats`）、`App.tsx` 里 `duration` 从 `<BeatRail>` 上摘掉，
测试是 `src/ui/segs.test.ts` 16 条，记在 README"已经排好的那一段不许跨一帧再排一遍"那一节。
方案里那四句大方向对了，三处和写的时候想的不一样，都得改在这里：

1. **"印出来的那一套"必须是排出去那一刻的值快照，不是那个活的 `Beat`（方案第 2 句的隐含假设错了）。**
   方案当时说"`now`/`armed` 不进 props，`b`/`i` 留着"，默认了"传那个 `Beat` 就行、它变没变 `memo` 自己会看见"。
   正好相反：解释器**原地**长那一拍（`cur.end = Math.max(...)`、`gate` false→true、`headline` 空→那句），
   `memo` 逐格比 props 的引用 —— 传那个活对象就永远是同一个引用，回头改的那一格**变了也不许重画**，DOM
   停在旧宽度与空台词上，而计数器照常加（形状层与价钱层全绿）。所以引入 `SegPrint`（`title`/`headline`/
   `ask`/`grow`/`turn` 全是定值）与 `samePrint`，回头那一格靠比这份值决定要不要重做。改前那条路为什么没
   露馅？因为它每批带一个 `total = duration` 在动，逼每一段重新 render，**顺手**把变了的那几样带了出去
   —— 它那点正确是靠要消掉的那笔冤枉钱撑着的。这一处的变异（`M2c 印的东西改成那个活的 Beat`）红 6 条。
2. **跨拍那一帧的钱不止"做段"，还有"逐格走一遍子树"这一格，前两把尺子都量不到（方案第 4 句少了一格）。**
   D 的第一版把段数组直接摊进 `<div className="beats">{segs}</div>`，"什么都不动的那一帧"从 0.035ms
   涨到 4.48ms@4800 —— 那个 div 每帧新建，React 拿到它就要把里面 n 个 child 逐格走一遍才知道有没有变，
   哪怕 child 引用一个没换。`railMeter.segs`（做段）与 `canReroll`（重画）对此**全为零**，抓不到。中间试
   `useMemo` 把那个 div 缓存成一个元素只降到 0.166ms（元素引用不变 React 仍走进那 n 个 child）；真正修掉的是
   把容器做成一个 memo **组件** `Beats`（0.036ms）。于是多了第三把尺子 `railMeter.boxed`（进容器一次加一，
   单独抽成 `countBoxed()` 是因为 `railMeter.boxed += 1` 直接写在 render 里撞 `react/immutability` 那条规矩）。
3. **"被点住那一格在哪一格"要查表（`atBySeq`），不许走整条 —— 这一问也是尺子量不到的（方案第 1、2 句没想到）。**
   `armed` 挂着时 `light` 每一帧都要答"那一拍在第几格"。写成 `beats.findIndex(...)` 不改印出来的值、一段
   不多做、一次不重画 —— 三把尺子全绿（`M19` 第一版就是全绿）。可它每一帧都跑、走的就是整条拍表，正是这件
   要消掉的那一笔。所以由 `absorb` 顺手记一张 `atBySeq`（跟着 `els` 一起长，和 `RowIndex.bySeq` 同一句），并
   按仓库旧规矩（`standing-tail.test.ts` 给道具表与流水各套一层 Proxy）**给拍表套一层 Proxy 只数读了几格**，
   单独钉一条。

还有一处方案里没说、做出来才发现的：`light` 越界那一格不再补守卫（第一版有），改成"由 `relay` 那句
`if (!b) return` 自己退" —— `now` 是调用方（`BeatRail` 那头的二分）给的答案，越界本就答"没有哪一格该亮"，
这一句不许炸；`M19/N7/N8` 三处变异把这件事钉清楚了（`relay` 那句退掉红 1，补守卫那一处全绿=防御）。

## E 的设计要点（日志那一头补上节拍条已有的那把尺子）

D 收尾点名的两笔里，`published` 那一笔已经钉死为**消不掉的诚实价钱**（React 认子数组的引用，长过尾巴就
得重新交一份指针），它只在真正脏的那一批付，与"经过不经过整棵 App"无关。剩下那一笔是**没被任何尺子量到的**：
日志面板在 `App` 里是一句裸的 `<div className="panel log">{logRows}{lines…}</div>`。`App` 是唯一的
`useSyncExternalStore` 订阅者，时钟每一帧整棵重渲染，那个 div 每帧是一个**新元素**，于是 React 每一帧都要
把那 n 行 child **逐格走一遍**才知道能不能跳过 —— `logRows` 那一份引用是稳的，所以走得很便宜（探针实测不动
的一帧 0.345ms@600 对 0.388ms@4800，比节拍条当年的 0.035→4.48ms 小两个量级），但它确实每一帧付、跟着带子长。

这一笔节拍条那头已经消掉了：D 把横滚的容器做成一个 memo **组件** `Beats`，配第三把尺子 `railMeter.boxed`。
日志这一头从来**没有对应的容器，也没有对应的尺子** —— `rowsMeter` 只数每批的 `described`/`published`，
看不见"不动的那一帧走了几行"。所以 E 就是把 D 那句照搬到日志：`LogRows`（memo 组件，住在单独的文件里，
和 `Seg` 因为 `react/only-export-components` 拆出去同一句）+ `rowsMeter.boxed`（门口加一，抽成
`countLogBoxed()` 是因为 `react/immutability` 不许在 render 里改模块外那个对象）。三层：

- 形状：不动的一帧 `boxed` 一次不涨（`view.test.ts` 那头，挂整棵 App 量，不是门）；脏一批进一次；带子换卷
  进一次。
- 价钱：短带与长带的"不动帧" `boxed` 增量都必须为 0 —— 这一句才是"那一帧走几行不再跟着带子长"。
- 护栏：日志的 DOM 行数仍然等于带子长度（memo 不许把新落那一行挡在画面外，和 C 踩过的坑同一句）。

## E 已经做完（这一节的实测与一处改判）

落地的是 `src/ui/LogRows.tsx`（那个 memo 容器，`react/only-export-components` 逼它住在单独文件里）、
`src/ui/rows.tsx`（`rowsMeter` 多了第三格 `boxed`，门口那句 `countLogBoxed()` 抽出来是 `react/immutability`
逼的）、`src/App.tsx`（那句裸 div 换成 `<LogRows rows={logRows} lines={lines} />`）、
`src/engine/view.test.ts`（新增三条），记在 README"日志那一排也交给容器自己那本账"那一节。

一处和方案写的时候想的不一样，得改在这里：

1. **这一笔的毫秒比方案预期小两个量级，但形状对得上：裸容器跟着带子长，memo 跟着带子缩。**
   E 的设计要点当时默认这是 D 那一笔（0.035→4.48ms@4800）的同款。实测：整棵 App 挂上，站在一拍里来回
   `seek`，各取五遍最小值 —— 裸容器 0.342→0.356→0.433ms（600 / 2400 / 4800 行），memo 0.332→0.325→0.257ms。
   差别不是"走一遍贵 40 倍"、是"走得便宜不等于没走"：`logRows` 那份引用本来就稳（C 那件早就换到手了），
   React 逐格比对每一行就是一个 `===`，比 D 那一头"div 每帧新建 → 里面的 map/filter 都要重跑"这一笔小得
   多。这一件换到的是"**每一帧付一次**"从形状上消失：改前带子越长那一帧越贵（线性），改后那一帧不进容器、
   与长度无关。**证据交给 `boxed` 那一格，不交给毫秒** —— 仓库的旧规矩本来就这么写着。

三把尺子这一件补齐（`described`/`published`/`boxed`），跟 D 那一头 `segs`/`published`/`boxed` 同一形状。
测试挂整棵 App 那一头三条 + 挂 `LogRows` 单独一棵一条，共四条。第四条是**跑完变异才补上的**：前三条
跑完后 `N2b memo 的比对器只比 rows、忽略 lines` **全绿** —— 一个改了行为却没有一把尺子的错法静了过去，
和 D 那一件 `M19` 同一句话。补上第四条直接挂 `LogRows` 逼它换 `lines`，`N2b` 当场红 1。

反向验证只跑一趟：忠实的历史替身（把 `LogRows` 退回那句裸 div、`countLogBoxed` 仍挂门口、四条测试正文
一字不改），**红 3 / 绿 1** —— 绿的正是那条**冻住护栏**：改前没有 memo，也就没有"memo 把面板冻住"
这一错法可测，那一条只能钉在新代码上（这与 D 那一头 `M2c 印的东西改成那个活的 Beat` 反过来：那一处是
新写法**独有**的错法，这一处也是新写法**独有**的错法，只是方向相反）。

变异九处（整棵 `view.test.ts` 的诚实计数）：N1 去掉 memo 红 3；N2 memo 永远相等 红 5（连挂载都冻，
两条 C 时代的旧断言一起红 —— E 里最响的一条）；N2b 只比 rows 忽略 lines 红 1；N3 永远不等 红 3；
N4 尺子搬到 memo 外 红 3；N5 App 每帧抄数组 红 2。三处**全绿**：容器多一个 `title`、`+= 1` 写成 `= x + 1`、
`filter` 的长度判等换写法 —— 等价，没有断言看它们，也不该有。

全套 384 → 388 条绿。这一件**没有旧断言要改** —— 四条测试全是新的，`rows.test.ts` 那一头一字未动。

## 现在剩下的价钱（E 之后，同一台机器）

| 时机 | 一笔 | 尺子 | E 之后 |
| --- | --- | --- | --- |
| 落一批（脏） | O(带子) 的**指针抄** | `rowsMeter.published` / `railMeter.published` | 仍在，消不掉：React 认子数组引用，长过尾巴必须换引用（C 实测钉过：带子 51 格、DOM 里 50 行） |
| 脏帧（落一批/跨一拍） | React 把 n 个 child **走一遍比对** | `rowsMeter.boxed` / `railMeter.boxed` | 仍在：容器 memo 只在"一个都没脏"那一帧免费，脏了就得走进那一排 |
| 不动帧 | ~~React 每帧走一遍 n 行~~ | `rowsMeter.boxed` | E 消掉了：那一帧 `boxed` 恒零（挂整棵 App 实测） |

前两笔要彻底消掉仍得给这两块面板一个**自己的订阅**：让"带子长了 20 格""时钟跨了一拍"经过的是那一块
面板自己那本账，而不是整棵 App。可形状上这一档不是照搬一件就完：要么改 `useSyncExternalStore` 的
粒度（把带子的引用抖动单独做成一个 store 只在日志面板订阅，把拍表换引用与亮哪一格单独做成一个 store
只在节拍条订阅），要么干脆把 App 拆到不订阅时钟那一层 —— 两者都要重新回答"什么算这一帧的输入"，
每一问都得先立一把自己的尺子。那是 F 那一档。

## 怎么证明它没改语义（仓库的三层）

- 形状：逐批对账，参照是"整条重排一遍"，不许复用缓存。
- 价钱：数**重做了几个元素 / 读过哪几格 / 进没进容器**，不依赖毫秒（共享 CI 的噪声比省下来的毫秒大）。
- 反向护栏：改前那份读法自己也得跑一遍（历史替身），原有断言不许为了变绿而改 ——
  只有当一条断言钉的**正是这一件消掉的东西**时才改它，并记在这里（D 改的是 `view.test.ts` 三条节拍条
  测试的入参 `duration`，断言正文一字未动）。
