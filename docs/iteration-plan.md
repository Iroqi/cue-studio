## 先学外部：OpenAI 的 Intelligent UI（2026-10-07/08 随 GPT-6 推送）

三条与本项目直接同构的设计事实：

1. **不是生成代码，是生成一种受限的界面语言。** 模型不写 HTML/JS，它吐一种自定义的 UI 语言，
   服务端编译，客户端在沙箱运行时里用约 70 个原生组件渲染。这和本仓库"模型只能交 markup，不能交
   代码；3D 是声明式图元表；`guard` 是白名单门"是同一条决定 —— 差别在于 OpenAI 把编译放在服务端，
   而这里编译（解释）在浏览器，因为"没有后端网关"是这个产品的前提。
2. **界面随生成逐步呈现，不等整段答案写完。** 原生可流式组件库 + 编译器，边生成边上屏。
   本仓库早就在这一头：`paint` 逐笔长在舞台上、`clock 不许跑在画面前面`（第二条时间规则）。
   Intelligent UI 值得学的不是"能流式"，而是**它把"什么时候该给界面、什么时候该给文本"当成
   模型训练目标**（清晰度/有用性/完整性三问），并把这条判断交给模型而不是交给 UI 分支代码。
3. **交互不再额外调模型。** 用户点了按钮、拖了滑杆，不再走一次 AI 调用 —— 界面自带状态。
   本仓库现在是**反过来的**：`ask_learner` 的答案落回带子（`answer` op），学习者点一下节拍条就剪带
   重排。这一条我判断**不该照抄**：这里的每次交互都是课的一部分，得留在带上；但 OpenAI 那句
   "交互不付费"戳中了另一件事 —— **本仓库的交互确实付费，而且付费的是观众那一头的整卷重排**，
   不是模型。这就是下面的两件。

对照之后剩下的判断：Intelligent UI 的方向是"回答即界面"，而 Cue Studio 从第一天就是
"回答即演出"。所以不该往这个仓库里加"生成式 UI 组件库"，该做的是把它那句工程承诺兑现到底：
**界面跟着内容长，而且长一截只付一截的钱。** 前者已经做了（三处续排），后者还没做完 —— 就差观众
那一头。

| --- | --- | --- | --- | --- |

## 候选方案

C. **（本件第一件）`logRows` 的整卷重排。** 就是上一份 plan 里那件 C，前提仍然成立：`describe`
   读只有自己那一笔的 `op` 字段，加上 `gates.get(o.gate)` 那张卡里**前面那一刀**落下的 `op.prompt`；
   被身后那一笔回头填的 `gate.said` 一个字也没印。所以它是**纯尾巴**，和 `TapeIndex` 同形、比
   `StandingIndex` 简单。
   改法照搬仓库已经立好的门形：`RowIndex` + `rerows(ix, compiled, tape)`，认的是**两张容器的引用**
   （`stage.log.tape` 与 `compiled.gates`）—— `append` 让带子长一截（引用不变 → 只排新落的那一截），
   剪带、载入、清空换数组（→ 整卷重排，那是诚实的价钱）。`Compiled` 那份记录每批都是新对象，所以
   `useMemo` 的依赖换成两张容器才是对的；这就是"引用抖动"四个字的正面解法。
   一处必须防的修过头：`RowIndex` 得挂在**带子**上而不是挂在组件里（`WeakMap<tape, RowIndex>`），
   否则"认引用"这一问在 React 那一头根本没有答案 —— 组件重挂、tab 来回切都该复用同一本账，
   而换带子必须换账。
   护栏按计划里那句立：`gate.said` 是一颗正被回头改的字段，今天不印不等于明天不印 —— 所以
   `rows.test.ts` 钉"印一个会被身后那一笔回填的字段，这一层的缓存必须红"（拿变异跑，记在下面）。

D. **（本件第二件）节拍条跨拍那一帧。** 同一句话的另一半：`Segs` 每跨一拍就把整条节拍条的
   段**重做一遍元素**，React 拿到的是全新引用，于是每一段都重新 render。改法还是那句
   "已经排好的那一截不许每批再排一遍"，只是这里长的不是尾巴而是**头上与身上各一格**
   （丢亮的旧 `now`、拿亮的新 `now`）：段元素按**落下次序**记住，跨拍那一帧只重做那两段。
   前提是把"这一段的宽度"从 `total` 上摘下来 —— 现在 `width: max(46px, share%)` 里的 `share`
   分母是整场长度，于是**落一笔也得整条重做**；换成 `flexGrow = 自己的毫秒数`，宽度由浏览器
   按比例分，段与段之比正是时长之比，`total` 一个字也不进 props。这是本件唯一一处**改观感**的地方，
   所以它得单独钉（比例、下限 46px、溢出仍然可横滚）。
   `armed`（哪一段被点准备重排）本来就在尾巴之外，跟着 `now` 同一句处理：只重做那两段。

C 与 D 分两次提交：它们的门形相同（认容器引用、只重做变过的那几格），可 C 的错法在"什么算变过的
一行"（答案行读前面那一刀的卡），D 的错法在"什么算变过的一段"（`now` 会**同时**动两格，
而 `total` 一动就是全条）。钉的东西不同，所以各走一遍仓库的三层。

## C 已经做完（这一节的实测与两处改判）

落地的是 `src/ui/rows.tsx`（`RowIndex` + `rowsFor(compiled, tape)` + `rowsMeter`）、`OpLog.tape`
那一个 getter、`App.tsx` 那个 memo，测试是 `src/ui/rows.test.ts` 13 条，记在 README
"已经排好的那一行不许每批再排一遍"那一节。两处和这份方案写的不一样，都得改在方案里：

1. **"交出去的是同一个数组对象"那句是错的。** 这一件原本打算直接交 `rows` 本身（引用不变 → React
   逐棵子树跳过）。实测：那些行是那个 div 的多个 child 之一，React 给它一个 fragment 节点，浅比对
   问的就是这个数组本身的引用 —— 引用没换就整串当没变，新落的那一行**永远进不去 DOM**（带子 51 格、
   DOM 里 50 行）。改成 `view()`：没动过交同一个引用，动过重新抄一份。留下的那笔"每批一次 O(带子)
   的指针抄"记进 `rowsMeter.published`，是消不掉的，除非给日志面板一个自己的订阅。
   探针第一版拿"数组是唯一的 child"试，那一头两种写法都进得去 —— 又是一次"探针得先证明自己量得到东西"。
2. **C 的依赖多了一处不是纯尾巴的东西**：`restore` 按号排，所以"答在问之前"是一卷合法的带子，那一行
   要等它的题卡进账才印得出题面。旧写法每批拿整张卡表重排整卷，隐式地付了这个答案；续排必须由知道
   改动的那一方（卡进账这一刻）回头补那一格。这一处是 `Waiting` 那张表，形状和 `StandingIndex` 的
   `touched` 流水一样，只是等的东西少到可以直接记下来。
3. `grow` 里"先收卡后排行"那个次序**不是语义**、是价钱：反过来那一行会先落进 `waiting`、同一趟
   `grow` 的收卡那一环当场补回来，答案对、多付一遍工（变异跑过：形状那两条全绿）。

都会碰到，一节课走到底要跨几百次。下面 D 的设计要点照旧，只补一句：`Segs` 那一头的浅比对问的也是
`beats.map(...)` 那个新数组的引用，所以 D 不能只靠 `memo` —— 它同样需要一个"记住段元素、只在变了
时换引用"的容器，和 C 是同一句话。

## C 的设计要点

1. `describe` 搬进 `src/ui/rows.tsx`，成为 `describeOp`；`RowIndex` 手上留三样：那张
   `readonly OpEntry[]`（带子本身）、`compiled.gates` 的引用、一个 `gateBySeq`（**只在吸收尾巴时
   长**的查表，不是每批拿整张卡表现建一遍 `Map` —— 那本身就是整卷的钱）。
2. 门与 `reindex` / `restand` 同形：`rerows(ix, compiled, tape)`。`holds` 两张都比（`tape` 与
   `gates`），只认 `tape` 的写法能把新落的那些行接到一本换了卡表的账上 —— 那一头 `answer` 行
   指不到它的题卡，红护栏里"只换卡表必须整卷重排"那一条。
3. 行元素按带子次序存在一个数组里，`absorb` 只往尾巴 push。返回的是**同一个数组对象**：React
   每帧比对整棵树时，未动的行引用不变就逐棵子树跳过 —— 这正是 C 要换来的那件事，也是
   `view.test.ts` 那件旧修改已经在用的那条规矩（"记住的必须是元素本身，不是每行的文字"）。
4. 三层：
   - **形状**：随机带子逐批追加，每批落下之后拿续排的 `rows` 和"拿这一批为止的带子整卷重排一遍"
     逐行对账（文本与 key）。参照不许复用缓存。
   - **价钱**：不量毫秒，数**这一层做了几次元素**（模块导出的计数器）。落一批只许做本批那几行；
     时钟走一帧一次也不许做；带子换卷那一条付整卷（诚实的价钱，钉住它不许偷偷变成常数）。
   - **护栏**：一次建完与逐批续排同解；内容相同换了数组必须重排；只换卡表必须重排；
     `answer` 行仍然认得题卡（`view.test.ts` 那条旧断言搬进来）；`said` 回填不许改已经排好的行。

## D 的设计要点

1. 段元素记在 `SegIndex` 上，认 `compiled.beats` 的引用（`beats` 是会长大的容器，和
   `cues`/`gates`/`props` 同一批）。跨拍不动 `beats`，所以尾巴之外只重做两格。
2. `now` 与 `armed` **不进 props**：它们是"哪一格"的事实，不是"这一格长什么样"的事实 ——
   改成缓存里那两格重做（旧 `now` 那一格去掉亮、新 `now` 那一格加上亮）。这样跨拍那一帧做的
   元素数 = 2，与带子多长无关。
3. 宽度换成 `flexGrow`，于是 `total` 从整条链上消失；`Seg` 的 props 只剩 `stage`/`teacher`/`b`/`i`/
   `now`/`armed`/`onArm` 里的 `b`/`i`/`now`/`armed` 四项，其中只有变过的那两格换引用。
4. 价钱那一层仍然数**重画次数**（`teacher.canReroll` 的调用次数就是段被重画的指纹，
   `view.test.ts` 早就在用）：跨拍那一帧至多两次；带子长一截只许新落的那几拍；
   走一帧不跨拍一次也不许。

## D 已经做完（这一节的实测与三处改判）

落地的是 `src/ui/segs.tsx`（`SegIndex` + `segsFor(compiled, view, now, armedSeq)` + `railMeter`
三格计数器）、`src/ui/Seg.tsx`（拆出来的段组件，仓库那条 `react/only-export-components` 逼的）、
`src/ui/BeatRail.tsx`（那个 memo 容器 `Beats`）、`App.tsx` 里 `duration` 从 `<BeatRail>` 上摘掉，
测试是 `src/ui/segs.test.ts` 16 条，记在 README"已经排好的那一段不许跨一帧再排一遍"那一节。
方案里那四句大方向对了，三处和写的时候想的不一样，都得改在这里：

1. **"印出来的那一套"必须是排出去那一刻的值快照，不是那个活的 `Beat`（方案第 2 句的隐含假设错了）。**
   方案当时说"`now`/`armed` 不进 props，`b`/`i` 留着"，默认了"传那个 `Beat` 就行、它变没变 `memo` 自己会看见"。
   正好相反：解释器**原地**长那一拍（`cur.end = Math.max(...)`、`gate` false→true、`headline` 空→那句），
   `memo` 逐格比 props 的引用 —— 传那个活对象就永远是同一个引用，回头改的那一格**变了也不许重画**，DOM
   停在旧宽度与空台词上，而计数器照常加（形状层与价钱层全绿）。所以引入 `SegPrint`（`title`/`headline`/
   `ask`/`grow`/`turn` 全是定值）与 `samePrint`，回头那一格靠比这份值决定要不要重做。改前那条路为什么没
   露馅？因为它每批带一个 `total = duration` 在动，逼每一段重新 render，**顺手**把变了的那几样带了出去
   —— 它那点正确是靠要消掉的那笔冤枉钱撑着的。这一处的变异（`M2c 印的东西改成那个活的 Beat`）红 6 条。
2. **跨拍那一帧的钱不止"做段"，还有"逐格走一遍子树"这一格，前两把尺子都量不到（方案第 4 句少了一格）。**
   D 的第一版把段数组直接摊进 `<div className="beats">{segs}</div>`，"什么都不动的那一帧"从 0.035ms
   涨到 4.48ms@4800 —— 那个 div 每帧新建，React 拿到它就要把里面 n 个 child 逐格走一遍才知道有没有变，
   哪怕 child 引用一个没换。`railMeter.segs`（做段）与 `canReroll`（重画）对此**全为零**，抓不到。中间试
   `useMemo` 把那个 div 缓存成一个元素只降到 0.166ms（元素引用不变 React 仍走进那 n 个 child）；真正修掉的是
   把容器做成一个 memo **组件** `Beats`（0.036ms）。于是多了第三把尺子 `railMeter.boxed`（进容器一次加一，
   单独抽成 `countBoxed()` 是因为 `railMeter.boxed += 1` 直接写在 render 里撞 `react/immutability` 那条规矩）。
3. **"被点住那一格在哪一格"要查表（`atBySeq`），不许走整条 —— 这一问也是尺子量不到的（方案第 1、2 句没想到）。**
   `armed` 挂着时 `light` 每一帧都要答"那一拍在第几格"。写成 `beats.findIndex(...)` 不改印出来的值、一段
   不多做、一次不重画 —— 三把尺子全绿（`M19` 第一版就是全绿）。可它每一帧都跑、走的就是整条拍表，正是这件
   要消掉的那一笔。所以由 `absorb` 顺手记一张 `atBySeq`（跟着 `els` 一起长，和 `RowIndex.bySeq` 同一句），并
   按仓库旧规矩（`standing-tail.test.ts` 给道具表与流水各套一层 Proxy）**给拍表套一层 Proxy 只数读了几格**，
   单独钉一条。

还有一处方案里没说、做出来才发现的：`light` 越界那一格不再补守卫（第一版有），改成"由 `relay` 那句
`if (!b) return` 自己退" —— `now` 是调用方（`BeatRail` 那头的二分）给的答案，越界本就答"没有哪一格该亮"，
这一句不许炸；`M19/N7/N8` 三处变异把这件事钉清楚了（`relay` 那句退掉红 1，补守卫那一处全绿=防御）。

## E 的设计要点（日志那一头补上节拍条已有的那把尺子）

D 收尾点名的两笔里，`published` 那一笔已经钉死为**消不掉的诚实价钱**（React 认子数组的引用，长过尾巴就
得重新交一份指针），它只在真正脏的那一批付，与"经过不经过整棵 App"无关。剩下那一笔是**没被任何尺子量到的**：
日志面板在 `App` 里是一句裸的 `<div className="panel log">{logRows}{lines…}</div>`。`App` 是唯一的
`useSyncExternalStore` 订阅者，时钟每一帧整棵重渲染，那个 div 每帧是一个**新元素**，于是 React 每一帧都要
把那 n 行 child **逐格走一遍**才知道能不能跳过 —— `logRows` 那一份引用是稳的，所以走得很便宜（探针实测不动
的一帧 0.345ms@600 对 0.388ms@4800，比节拍条当年的 0.035→4.48ms 小两个量级），但它确实每一帧付、跟着带子长。

## F 的设计要点（跨拍那一帧：节拍条不再按整条拍表付钱）

E 之后，探针把"还剩哪一笔跟着带子长"照清楚了（三种帧 × 两把尺子 × 两种带长，跑完就删）：

| 帧 | `railPublished` | `railBoxed` | `railSegs` | `logPublished` | `logBoxed` |
| --- | --- | --- | --- | --- | --- |
| 不动（站在一拍里来回 seek） | 0 | 0 | 0 | 0 | 0 |
| 落一批（带子长 20 格） | O(带子) 一次 | 1 | 本批那几拍+1 | O(带子) 一次 | 1 |
| **跨一拍（带子没动）** | **O(带子)** | **1** | 2 | 0 | 0 |

**不动帧六把尺子全零**——E 那一笔确实消到底了，F 不能再靠"再消一次不动帧"立项。落一批那两笔 `published` 是
C/D 钉死的诚实价（带子真长了，React 认子数组引用，必须换引用），F 不动它。**剩下唯一一笔还在按带子长的，
是跨拍那一帧的 `railPublished`/`railBoxed`**：带子一个字没动，只是"亮着哪一格"从这一拍挪到下一拍，可今天
`segsFor` 见 `now` 变了就 `relay` 两段 → `published=null` → `take()` 把整条拍表重新 slice 一遍（抄的全是指针、
O(带子)）→ `Beats` 拿到一份新数组引用、容器进门把 n 个孩子逐格走一遍（O(带子)），只为挪动那一格高亮。

这一笔日志面板没有：跨拍不动带子，`logRows` 那份引用本来就稳，容器 memo 直接驳回（探针 `logPublished`/`logBoxed`
恒零）。所以 **F 只做节拍条那一头**。

病根和 D 消掉 `total` 是同一句话：**"亮哪一格"是"哪一格"的事实，不是"这一格长什么样"的事实**，它不该编进那份
子数组、逼整条换引用。D 当年把它留在 props 里、用"跨拍只重做两格元素"挡住了"做段"那一半，可"重新交那一份数组"
和"容器走进那 n 格"这两半没挡住——因为它们要的不是"重做几段"，是"数组引用换没换"。E 用 memo 容器挡住了不动帧
那一半，唯独挡不住跨拍：跨拍时数组引用**真的**换了（`take()` 重新 slice），memo 驳不回。

F 的解法：把 `now` 从"父交给数组"降成"**每段自己订阅那一句 `此刻是不是我`**"。探针（跑完就删）钉住了这条能走：
一个 `useSyncExternalStore` 快照比较用的是 `Object.is`，所以**同引用、原地改值的快照根本唤不醒**（`renders=1
seen=0`）——叶子必须订阅一个**会变值的派生布尔** `store.get() === i`，不是订阅那个每帧都换的 `now` 数字（订阅数字
→ 全 n 段每帧都醒，比现在还差 n 倍）。派生布尔那一头实测：

| 帧 | 醒的段 | 进容器 |
| --- | --- | --- |
| 冷启 `now`→某拍 | 1 | **0** |
| 不动（同一拍） | 0 | **0** |
| 跨拍（旧亮熄、新亮起） | **2** | **0** |
| 收亮（走出拍表） | 1 | **0** |

数组引用跨拍不换、容器一次不进、只有那两格翻面的段自醒——和今天 `relay` 重做的段数是同一个常数 2，但把"重做段"
之外的两笔 O(带子)（重新交数组、容器走一遍）从形状上消掉了。

落地形状：
1. `now` 不进 `segEl`/`Seg` 的 props；每段 `Seg` 自己 `useSyncExternalStore(sub, () => nowStore.get() === i)`，
   `data-now`、`className` 里那个 `now` 由这个派生布尔决定。`SegPrint` 一个字段不动（它本就是"印出来"的定值，
   亮不亮不是"印什么"）。
2. 那一台 `nowStore` 和 `SegIndex` 同生命周期：挂在 `cached` 那条拍表的引用上（WeakMap），换卷 → 新拍表 →
   新 store → 整条重排（诚实价，和 `segsFor` 认引用同一句）。`segsFor` 每一帧只做一件事：把 `now` 喂给 store
   （`store.set(now)`，值没变就 `return`、一次都不 notify），**不再 slice 数组、不再 relay 亮灭那两格**。
3. `light()` 只剩 `armed` 那一半（点住/放开是用户动作、罕见，仍 relay 那一两格，付一次换引用是诚实价）；
   `grow()` 尾巴那半不动（新落的段构造时读当前 store 的 `now`，第一帧就印对）。
4. 三层，尺子就落在探针照出的那一格上：
   - **形状**：DOM 上"亮着的那一段"仍逐拍移动，且任何时刻恰好一段（`.seg.now` 恒 ≤1）——派生布尔不许把高亮
     落错格、也不许两格同时亮。
   - **价钱**：跨拍那一帧 `railPublished` 增量 **0**、`railBoxed` 增量 **0**、醒的段 ≤2（挂整棵 App 那头的时钟
     走拍量，不是门）；落一批仍付 `published` O(带子)（不许偷偷把这一笔说成已消）；不动帧三把尺子仍全零（不许
     把 E 的免费还回去）。
   - **护栏**：亮灭、回头改那一格、点住那几格在**真 DOM** 上都对得上（沿用 `segs.test.ts` 那条 DOM 护栏的
     `widths()`/`cls()` 复核对）；`nowStore` 认拍表引用，换卷必须换 store（否则新拍表读到旧 `now`）。

一处必须先自证、否则探针不作数（C/D 立的规矩：探针得先证明自己量得到东西）：**反向**——忠实退回"now 进 props、
跨拍就重新交数组"的写法，同一批 F 新测试必须红（红在跨拍那一帧的 `published`/`boxed` 上），绿在不动帧上
（那一帧改前改后都免费，是 E 的功劳，不是 F 的）；只有 F 真正消掉的那笔才红。

# 第二轮 brainstorm（2026-10-12）：Intelligent UI 的 Rough edges 里，哪一件是这一仓库的

## 重新读了一遍 Intelligent UI（openui.com 的逆向拆解，GPT-6 随 ChatGPT 上线）

第一轮（C-F）从 Intelligent UI 拿走的是三件"同构"（受限界面语言、流式呈现、交互不付费），判断
"回答即界面"不是这个仓库的方向，"回答即演出"才是。这一轮把那篇拆解的 **Rough edges** 一节逐条过
了一遍 —— OpenAI 自己列出的那些缺点，每一件都是一个"它没做到、我们能不能做到"的问题：

| Intelligent UI 的 Rough edge | ChatGPT 的现状 | Cue Studio 的现状 | 判断 |
| --- | --- | --- | --- |
| 刷新后状态丢 | 滑块值存到 view-state 端点但不恢复 | 带子 = 状态，`#s=` 里 deflate 整卷，刷新原样重放 | 我们赢，吸收过了 |
| 后续问题重造整块界面 | 每个 follow-up 都是新程序 | 带子只增不删，revision 叠层，接着讲就是接着演 | 我们赢，吸收过了 |
| 流里 83% 是重发的代码 | 每几百毫秒整段重编译重发 | C-F 把"长一截只付一截"做到底 | 我们赢，吸收过了 |
| **逻辑错误是静的** | 一个表达式抛错只少一个元素，算错的值照样上屏（仪表盘 $6,930 → $256,410） | 解释器是纯函数，导演的错误落在**门**（`guardOp`）和**回执**（`hasFrame`/`onStage`/`blindCamera`）两层 | 门那一层是静的 —— 见下 |
| **非法属性没有反馈** | 编译器记 diagnostics，但**模型看不到**（同样的错后面继续犯） | 门把坏字段默认掉，导演的回执说"built X"，一个字不提门改了什么 | **同一个坑，见下** |
| 布局写死、不用断点 | 固定列数与像素宽 | 无界平面 + 运镜，没有"断点"这回事 | 不适用 |
| AppBlock 与宿主隔离 | iframe 里状态自持、不回调 | 仓库明确不要 JS 沙箱，`scene3d` 是数据不是代码 | 不适用 |

## 选定：门拦下来的东西，导演得知道（gate diagnostics → 回执）

仓库自己立的那条规矩叫"**回执不许替带子说话**"：`blindCamera` 说"镜头点名的东西观众看不见"、
`fetch_prop` 说"只被 link 念到过名字"、`hasFrame`/`onStage` 说"这一刀不落"—— 每一处都在杀
"模型把静默读成动过了"。**唯独门是静的**：`guardOp` 把 `camera.at={x:2,y:-1}` 夹回 0..1、
把 `narrate.text` 截到 2000 字、把 `duration:1e18` 封顶 120 秒、把 `motion.mode="levitate"` 回退
oscillate，回执照样说"narrated 52 chars"。导演接下来那一拍就建在一个没落地的假设上 —— 和
Intelligent UI "同样的错后面继续犯"是同一件事，只是我们的编译器（门）连 diagnostics 都不记。

改法照仓库已立好的形状：**门改了什么，回执就说什么**。diagnostics 只走导演那扇门（`append` 的
听筒），进不了带子、不碰重放、restore 路径门外没有人不听 —— 和 `live=false` 录像不提问是同一句。

## 设计要点

1. `guardOp(op, notes?)`：第二个参数是一个 `(n: string) => void`。每个 case 先把修正值算成本地量，
   `revise` 照旧是唯一落笔的地方；`notes` 提供时才逐字段比原值、把**改了什么**说成一句中文。
   干净的一刀：`revise` 原样返回同一引用（`out === op`），一个字也不说。修过的 op 再进门：
   已经干净，没有第二句话（幂等）。`notes` 不给（restore 路径、测试、所有现有调用）：
   行为与现在逐字节一致，连 `if` 都不进 —— 价钱层的第一句是"诊断是修正的副产品，不是批量的税"。
2. 报什么、不报什么：**只报真修正**。字段缺失走设计默认（`mode` 缺省 fit、`label` 缺省 id、
   `duration` 缺省 900ms）不报 —— 那是导演没给，不是门改了它；字段给了但被截断/夹回/回退/丢弃
   才报。数量 = 被改的字段数，与带子长度、批量大小无关。
3. `OpLog.append(ops, track, onNote?)` → `Stage.append(ops, track, onNote?)` 原样传听筒。
   `loop.ts` 的 `execute()` 只给**导演自己那批动词输出**挂听筒：paint 的占位框、reroll 的 discard、
   answer 的落带都是内部落笔，不在听筒范围。restore 根本没有听筒参数（门外没有人）。
4. 回执格式：有修正才加后缀 `\n（门拦下的：…；…）`，没有修正一个字也不多。与 `blindCamera` 那句
   并存：修正的话在前，镜头的话在后。
5. 带子一条诊断都不进：听筒是落笔的副产品，`tape` 还是那批 op。分享链接、重放、重排语义全不动。

## 三层（照仓库老规矩）

- **形状**：脏 op（超长 text、1e18 duration、不认的 mode/axis、越界 at/zoom/answer、超项 options、
  坏 gate、图元封顶、与板同色背景）逐条断言"修正值正确 + 笔记一条不落 + 措辞钉死"；干净 op
  同引用出去、零笔记；修过的 op 再进门零笔记（幂等）；带 notes 与不带 notes 吐出的 op `toEqual`。
- **价钱**：一百格干净的批零笔记；一百格里三格脏只报三格（数量是修正数，不是批量）；restore
  路径没有听筒参数、门外没有人。
- **护栏**：同一批 op，带不带听筒落下的带子逐格相等、长度相等，序列化后一个诊断字都不含；
  听筒只长在 `append` 那一扇门。

## 落地形状

`src/engine/guard.ts`（`guardOp` 加第二参 + 各 case 逐字段对账）、`src/engine/log.ts`、
`src/engine/runtime.ts`（传听筒）、`src/agent/loop.ts`（`execute` 挂听筒拼回执）、
新测试 `src/engine/guard-notes.test.ts`、README 新增一节、本文件补完实测与反向验证。

# 第三轮 brainstorm（2026-10-13）：Intelligent UI 的第三张卡 —— 不是认，是估

## 前两轮走到哪了

第一轮（C–F）从 Intelligent UI 拿走"受限界面语言 / 流式呈现 / 交互不付费"，兑现成三处增量续排；
第二轮（门的回执）从 Rough edges 拿走"非法属性没有反馈"，兑现成 `guardOp` 的听筒；
probe（f34fdac）拿走"可选中部件"，把答案从文字卡搬回台上。三张卡到齐了两张：
`quiz`（读一串文字选项）和 `probe`（点台上一个现成的形状）。

## 再读一遍那张拆解，问：还剩哪一种"碰"没有

Intelligent UI 的例子里有两类动作被混着说：一类是"选/点"（buttons、selectable parts），
一类是"拨/输"（sliders、calculators、editable charts）。本仓库只 import 了第一类。
"这根弹簧 k 大概多少""起飞速度得多大""这个角仰还是俯"——这种问题的教学目的不是**认**一个现成
答案，是**估**一个量。给一串选项是让他认你写好的数，让他点台上形状是让他认你画好的图；
两样都在考"认得"，而量级、方向、数量级那点物理直觉，只能让他自己拨出来。

## 选定：第三张卡 `dial`（动词 `tune`）

和 quiz/probe 同一张停表的卡，复用全部既有账本（停表、`waitForGate`、作答落带可重放、
live=false 录像不问、按 concept 记反复错过），唯一差别：**答案是一个数，按距离判**
`|his - value| <= tol`。杆是舞台自己渲染的原生 `<input type="range">`，不是模型交的
markup —— DOMPurify 那道信任边界一个字没动，陌生人的 `#s=` 带也只能给一段区间，给不出脚本。
他拨的那一下不进带子，落带的只有确认那一刻的那个数（probe 落带一个 id 的同一件事）。

## 三层（照仓库老规矩）

- **形状**：停表落成 gate、确认的数作为 answer 落带、load(live=false) 不开卡 —— `dial.test.ts`
  11 条（门 4、工具 4、演出 3），照 probe.test.ts 同形。
- **价钱**：这一件不新增每帧的钱 —— 杆只在时钟停在这一格时挂着，和 quiz 卡同生命周期；
  解释器那一头只多了一个 `case "dial"` 落到已有的 gate 分支里，cue 表、两本索引一格没动。
- **护栏**：区间倒挂交换、空区间撑开、value 越界夹回、吞段的 tol 夹到半段；工具那头
  min>=max / value 越界 / 非数字直接不落笔（回执不许替带子说话那条老规矩）。

## 落地与实测

`types.ts`（DialOp + Op 并集 + Gate.kind）、`guard.ts`（case "dial"，量级照 MAX_MS 那一套夹）、
`compile.ts`（gate 分支与 headline 各加一个 kind）、`tools/director.ts`（动词 `tune` + 工具定义）、
`agent/loop.ts`（settleGate 第三支，按距离判，archive 用 [他拨的, 正确的] 两项落一次）、
`App.tsx`（DialCard：range + 读数 + 确认）、`index.css`（.dial 一族）、`agent/prompt.ts`
（语法里加一条"要考量感时用 tune，别给选项"）、新测试 `engine/dial.test.ts`。

tsc / build / oxlint（仍是那 2 条既有基线警告，0 新增）干净；vitest 全套 416 → 427 绿

# 第五轮 brainstorm（2026-10-14）：逃生舱口 —— 他不会的时候，那句话自己就是出口

## 前四轮走到哪了

四张卡到齐了四种"碰"：read（quiz 读选项）/ tap（probe 指台上图形）/ dial（tune 拨一个数）/
type（type 说一句话）；回执那件（门拦下的导演得知道）与增量续排那件（长一截只付一截）也都兑现了。
每一件都是从 Intelligent UI 那张拆解里拿一条、对照"这一仓库有没有"再动手。

## 再读那张拆解：还有一条设计原则没 import —— escape hatches / trust the user

拆解的原则那一节有两条一直没进这一仓库：

- **Provide escape hatches**：用户在界面里要有出口 —— "show your work"、让用户接管、能退回文本。
- **Trust the user**：用户说不对、说不会的时候，信他，别跟他的自主权较劲。

仓库现在缺的正是这个。四张卡都是**停表的卡**：时钟停住，学习者的出口只有两个 —— 答这张卡
（判分、进档案），或在底下 console 打字（**照样算作这张卡的 `answer`**，占位符写着"不选也行 ——
直接说你怎么想的，这就当作对那个问题的回答…"）。"我不会"三个字打在 console 里，落到带上是一条
`answer`，`settleGate` 必须猜它是一句求救还是一句答错：type 卡那一头把它判成"缺了：瞬时、变化率"，
UI 的回执气泡跟着显示"还缺几个词" —— 学习者说他不会，界面告诉他你答错了。这正是拆解里
Rough edge"逻辑错误是静的"在学习者那一头的样子：**界面把用户的求救读成了错误答案**，和
Intelligent UI 把算错的仪表盘值照样上屏是同一件事，只是这一头错的不是计算，是意图。

## 选定：四张卡上各开两扇逃生门

改法照仓库已立好的形状，**不加新 op、不开新门、不动编译**：`answer` 本来就是"他说的话 + 他答的是
哪张卡"，所以"我不会"也是他说的话 —— 判分的权力在 `settleGate`，让它先认两句**约定的短语**再谈判分：

- `我不会`（按钮"我不会 · 换个讲法"）：求救信号 —— 换一种载体重演同一个 concept 再问一次。
- `跳过这道`（按钮"这道先跳过"）：他的选择 —— 尊重它继续往下讲（或记未掌握稍后再回来）。

这两句不进档案（`archiveAttempt` 一个字不碰）、不算错过（`missesOn` 不涨）、判分不碰。
回执给导演的是一句人话，不是一句改卷的判词 —— 和门回执那件同一条规矩："模型把静默读成动过了"
要杀，这里要杀的是"把求救读成答错"。

## 三层

- **形状**：四张卡（quiz / probe / dial / type）上任意一张，答 `我不会` 或 `跳过这道` →
  answer 落带（`text` 就是那句）、卡合上（`said` 是那句、`currentGate` 归 null）、回执是信任句
  （含"我不会"／"跳过这道"，不含"答错"／"缺了"／"没在容差"）；回放（`live=false`）时不开卡，
  他当时那句照旧从带子上读出来。scripted 排练那一头：导演的 ask_learner 卡住后答一句逃生的，
  工具结果里就是信任句。
- **价钱**：这一件不新增每帧的钱 —— 两个字符串比较只在 `settleGate` 落答那一刻跑一次，
  帧路径一个字没动；按钮只在卡开着时挂出来，和卡同生命周期（dial/type 那一头的老规矩）。
- **护栏**：答完这张卡之后逃生按钮随之消失（卡已合上，没有第二扇门可逃）；逃生不写
  `localStorage` 档案（Attempt 一个不增）；他自由打字"我不会"（不按按钮）也走同一条信任句
  （console 那一路本来就把他的话当 answer 送进来）；`pause_for` 不加逃生门（那不是考题，
  "继续"就是它唯一的出口）。

自由文本的未分级路径（导演照样读得到），没有断言钉它 —— 那是"按钮是正门、打字是侧门"的既有
语义；`pause_for` 不加逃生门（那不是考题，"继续"就是它唯一的出口），没有断言钉它。

放后面 quiz 会先当"没选选项"、type 会先当"缺了词"，门就白开了。
