# 迭代方案（brainstorm 记录）：两本索引续排 + 带尾那一截的引用抖动

## 仓库现在的形状

`main` = f5ca646。335 条测试绿。上一件把解释器搬进一台活着的机器（`Interpreter` / `perform`），
带子长一截就只演那一截；README 末尾留下两笔仍然每批整本重建的账，而且写明它们**现在是主要价钱**：

- `TapeIndex` / `StandingIndex` 每批整本重建（`runtime.ts` 的 `recompile` 每批 `new` 一次）
- `App` 那边 `logRows` 的引用抖动（`useMemo` 的依赖是整个 `Compiled` 记录，而它每批都是新对象）

A（`TapeIndex`）与 B（`StandingIndex`）都已落地，见下面两节各自的设计要点与 README。
剩下的候选只有 C：`logRows` 的引用抖动。

## 量过的基线（同一台机器，一次取七遍最小值）

先看单次重建的价钱随带子怎么长（一批 12 格：道具、镜头、旁白、强调、运动、换场、卡、撤下）：

| 4800 格（400 批） | 3200 | 800 | 400 | 0.510ms | 0.478ms |

单次重建这一列噪声很大（4800 格那一档比 2400 格那一档还便宜），它只能说明一件事：**它随带子长**。

## 候选方案

A. **（已做，见下）`TapeIndex` 续排。** 它是纯尾巴的账：cue 表只往后长、卡表只往后长，
   所以"续排"就是"只吸收新落的那一段"。唯一不干净的是开卡表 `openAt` —— 卡被答掉是**中间那一格换了状态**。
B. **（已做，见下）`StandingIndex` 续排。** 它比 A 险：外观的窗口两端会被身后的刀**回头盖住**
   （`layRevision` 给上一格补 `off`、`markOff` 补 `off`、填占位符把最后一格**原地换掉**），
   所以"只吸收尾巴"在这里不够，得处理"已经进过账的一格换了事实"。答案是让**知道改动的那一方**
   记一笔流水（`Compiled.touched`），而不是让读的人去重扫道具表。
C. **（下一件）`logRows` 的引用抖动**（方案 D 的旧编号）：A/B 之后带尾那一批在 view 里的价钱。
   `useMemo` 的依赖是整个 `compiled` 记录，而它每批都是新对象（`Interpreter.result()` 造的是一份新记录，
   里面那些容器才是会长大的那几张）—— 于是每来一批，整卷的行**逐行重做一次 React 元素**，
   `stage.log.all()` 也整卷走一遍。省下来的正是 A/B 那一串在同一处付的钱，只不过这一头付在 React 元素上。
   改法是把依赖换成 `log` 与 `gates` 那两张容器的引用、并按 `seq` 记住已经排好的那些行，只重做尾巴。
   **先要问清的是"什么算变过的一行"**：翻过 `describe` 一遍，它读的只有自己那一笔的 `op` 字段，
   以及 `gates.get(o.gate)` 那张卡里**前面那一刀**落下的 `op.prompt` —— 而被身后那一笔回头填的
   `gate.said` 一个字也没印。所以今天这一头是**纯尾巴**的，和 A 同形、比 B 简单。
   但这句话必须由测试钉住：`gate.said` 就是一个正被回头改的字段，哪天有人把它印进日志（"他答过了"），
   按 `seq` 记元素就当场是错的 —— 所以 C 的护栏里得有一条"往日志里印一个会被身后那一笔回填的字段，
   这一层的缓存必须红"，否则它是留给下一件的一颗雷。

A 和 B 一起做、分两次提交：两本索引的续排前提是同一句（认的是 `Compiled` 里那几张**会长大的容器**的
引用，不是那条带子），但它们的错法完全不同，钉的东西也不同，所以各走一遍仓库的三层。

## A 的设计要点（已落地）

1. `Compiled` 里的 `cues` / `gates` 是同一批只增的容器（`Interpreter.result()` 的注释就写了这件事），
   所以续排的认带子那一问换成引用：`holds(compiled)` 比这两张容器的引用。
   换了机器（剪带、载入、清空）就是换了数组，那一头整本重建 —— 和解释器那三扇门同一个政策。
   门写成模块函数 `reindex(ix, compiled)`，与 `perform(it, entries)` 同形。
2. 所有窄表都是 cue 表按落下次序的**子序列**，所以它们也只长尾巴；两条前缀最大值
   （`camMaxEnd`、`hlMaxEnd`）的游标（`camMax`、`hlMax`）搬进字段，续排从上一次那个数接着记。
   一格 cue 分进各条窄表的那一句（`absorb`）一次建完和续排共用，所以差异只可能来自分表的规矩。
3. `openAt` 是唯一会被中间改动的账：`said` 从 `null` 换成一句话，是身后那一刀的 `answer` 干的。
   续排不许每批把整张卡表重筛一遍，所以它换成**惰性作废 + 顺手压实**：
   - 新落的卡往表尾接（`said === null` 才接），这是本批的钱；
   - 表头那一截被答掉的，问的时候逐条迈过去（`head`），迈过去的那一格永不回头问第二次；
   - 全表那一问（`openGateSeqs`）筛掉作废的，**筛剩不到一半才把表换掉**。
   第三条治的是"答在中间的那些"（`head` 迈不过去）；而它不许写成"一发现有作废就换表"，那样每轮抄一次
   表，抄的还是整张表的长度。这一处是本次唯一一处**量不到**的规矩（那一层省的是内部数组的拷贝，
   不是卡表上的读数），所以它写在注释里而不是断言里。
4. 一处要防的修过头：`cue.to` 会被换场那一刀**原地改写**（`transition` 先落一条站着不动的 cue、
   再把落点写进去）。它改的是 `pushCue` 那一条，也就是本批尾巴里的最后一格，索引读到的一向是改完的那份 ——
   但这条规矩得有人钉，否则下一件把它挪到"边走边记"就当场破了。

## B 的设计要点（已落地）

1. 认台面同一句引用：`compiled.props` 是那张只增的道具表，`StandingIndex` 手上留着它，
   门与 `reindex` 同形（`restand(ix, compiled)`）。**实际比两张**：`props` 与 `touched`。
   只认 `props` 的写法能把旧索引接到一条换了流水的台面上 —— 红"拷贝一份同样内容不许被认成同一张台面"。
2. 那一句"已进账的一格的 `off` 会被身后那一刀补上"是这件事的全部难点，答案不由索引去猜，而由
   **知道改动的那一方记一笔流水**（`Compiled.touched`，四种 `prop` / `lay` / `close` / `fill`，只长尾巴）。
   于是那一问（"补的那一条落在哪个位置"）有了明确答复：流水里每一笔的时刻都是**它落下那一刻的时钟值**
   （`close` 的 `off` 取 `rev.t` 而不是那一格现在的 `off`），带子的时钟单调 ⇒ 流水本身就是排好序的事件流，
   续排是纯 append，中间插入一次也不许有，`moveTo` 的游标前提不破。反过来若去读那一格**现在的** `off`，
   同一批里身后那一刀补上的值会被先读到，事件流当场不再单调 —— 这就是价钱层钉住的那句"不许回头读"。
   建表与续排因此共用同一句 `absorb`，上一件钉 cue 表用的是同一句话。
3. 空窗口不是坑，量出来它根本不需要作废那一条：`build` 紧跟 `discard`（中间没有占时钟的一刀）时
   流水里是 `lay` 后 `close`、两者同一刻，游标把这一对当一步走完（前进 put 再 take、倒带 take 再 put），
   两头都答"这一刻台上没有它"。唯一要钉的是**流水里 `lay` 必须排在同道具的 `close` 之前**，
   而这就是落笔先后本身。另一头反过来：同刻换板重画时上一格的 `close` 必须排在新格 `lay` 之前，
   否则 `take` 那句"只有它还代表这个道具时才收"当场退出，旧板头上留下已经搬走的一格 = 两层。
   第三条筛（`born-closed`）治落笔就带 `off` 的那一格：`onstageAt(rev, rev.t)` 答否，它不进事件流，
   和建表那一遍同一个谓词。
4. `fill` 是唯一一次真的动已经进账的格子，而且**它带板**：Stand 握对象引用所以那一格的 `rev` 跟着换，
   换了板就得在板的分队列里挪窝。挪窝不许写成接尾巴 —— 换上去那一格的 `t` 是它**当初**落笔那一刻，
   可能早就在身后了，接尾巴会把那一列排出 `(t, rank)` 之外的次序，二分从此给错区间。
   板的头等表（`lines` / `lineLast`）的 `settle` 必须**双向**：换上去的那一格的 `last` 可能比现存各头都早，
   只会往右挪的二分会把这一头条在头表里放错位置（第一版就往右挪，`removeFromLine` 那里当场炸）。
5. 三层照旧，价钱那一层里"什么算回头"定在**容器**上而不是刻点上：道具表一次也不许走（`sweeps`/`cells`
   两个零），流水那一头往前读的至多本批新接的那几笔（`ledgerRead === 本批新增笔数`）。
   另钉一条"号在道具**进表**那一刻发"（`link` 只点了名的那一格漏了会红 7 条）。

## 怎么证明它没改语义（仓库的三层）

- 形状：随机带子逐批追加，每批落下之后拿**续排的索引**回答每一问，和**拿这一批为止的台面新建一本索引**
  逐刻对账（每一问在一批刻点上比，刻点含窗口边缘与边缘之间）。参照不许复用。
- 价钱：给容器各套一层 Proxy 数**按下标读了几格**（A 是 cue 表与卡表，B 是道具表与那条流水）。
  续排时回头读过的格子必须为 0，往前读的只许是新落的那一截。这条不依赖毫秒。
  B 那一头"什么算回头"定在**容器**上而不是刻点上：落一笔的时刻确实会回头（补上的 `off` 在已吸收的区间里），
  但读过的东西只许是本批新接的那几笔流水，道具表一次也不许走。
- 反向护栏：一次建完的答案不许因为换了读法就变；换了数组必须重建；旧写法那份参照自己也得跑。
