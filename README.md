# Cue Studio

一个 LLM 驱动的教师agent。它的媒介不是幻灯片，是一块无界的二维舞台平面（backstage）和一架摄影机 —— 知识被**演**出来，不是被列出来。

## 为什么它不是一个 artifact

常见的 AI artifact 是编译型的：模型一次生成一个成品。这里相反。

模型每次调用只发出一条 `op`（"说这句话，12 秒"、"把这支向量放到板上"、"镜头推到箭头尖"），追加进一条**只增不删的日志**。解释器把日志演化成舞台：道具表、时钟、镜头轨迹、门（gate）。成品不存在，只有过程 —— 这是"解释型"和"编译型"的区别。

推论：一堂课 = 一段磁带。所以分享（日志 deflate 后塞进 URL hash）、重放、从任意一拍截断重排，全都是日志的副产品，没有一个是单独实现的功能。

## 词汇

代码、提示词、UI 用的是同一套词，没有第二套命名。

| 词 | 是什么 |
| --- | --- |
| backstage | 无界二维平面。一场戏约 1600×900 单位，场景之间相隔 2000~3000。**一块被命名过的板就有位置**，哪怕它还是空的（`BOARD_SPACING = 2400`，按演出走上它的顺序排开）—— 否则切过去的那一刀没有地方可去 |
| prop 道具 | 平面上有身份的对象。**id 跨场景持续** —— 第三幕那个箭头仍然是第一幕那一个 |
| revision | 同一道具的一次外观变更（画错了重画、补细节），带自己的 `box` 和一段窗口 `[t, off)` —— `off` 是被 `discard` 撤下的那一刻，`undefined` 就是到带子尽头还站着 |
| cue | 一次工具调用 = 一个 cue，落在舞台时间轴上 |
| beat | 刻意的静默，让画面自己站住 |
| gate | 停时钟等学习者的地方：`ask_learner` / `pause_for` |
| tape | 日志本身，可导出、可分享、可重演 |

学习者也是台上的人，所以他说的话也在磁带上：`answer` 是新加的一个 op，由舞台在他回答的那一刻落下，只记内容和他答的是哪张卡，**不占时钟**。这一条把三件事变成副产品 —— 分享出去的录像带着他答错的那句话（那是一堂课里最值钱的上下文）；重放知道哪些卡已经答过；剪断某一拍重排时，他的回答跟着那一拍一起回去，因为那是它唯一存在的地方。于是"已答/未答"不再是运行时另外记的一本账，而是从带上读出来的事实。

配套的一条决定：**录像不再向看的人重新提问。** `live=false` 时 `currentGate()` 恒为 null，进度条一路走到底不会卡在别人的题上 —— 点开链接的人是来看的。想真的上这门课，接着说一句，板子从那一刻起变回 live，下一张卡就停在他面前。

## 时间规则（最要紧的一条设计）

只有 `narrate` / `beat` / `transition` **占时钟**。`camera`、`highlight`、`motion` 是叠在旁白之上的覆盖层，不推进时间。

覆盖层到点就走，不留痕：`highlight` 的四种里，`dim-rest` 是唯一打在**板子**而不是打在道具上的强调 —— 被点名的那块保住亮度，其余的退到后面（类名挂在 `.world` 上，因为"其余的"没法写进一条道具选择器里）。

所以"这一段讲多久"由旁白决定，运镜不能把课拖长。`motion` 的位移是**舞台时间的纯函数**（oscillate / approach / orbit / iterate / flow）—— cue 一结束道具回到它的锚点，倒带回去它也在那个位置。

道具的坐标是它的**锚点**，不是某一帧。想让一个东西自己动，是发一个 motion cue，不是一帧帧重画。

第二条规则：**时钟不许跑在画面前面**。首次演出时，只要镜头框住一个还没有任何图形的空框、而它的 `paint` 正在进行，`tick()` 就不推进 `t`（`playing` 保持 true，rAF 继续转，所以美工一交图它自己接上走）。美工开始流式吐线的那一刻就放行 —— 3b1b 的节奏是"边画边讲"，毛病出在"讲完了画还没出现"。重放时 `live=false`，画面早就在日志里，不需要等。

第三条规则，和第二条同一条：**也不许跑在没有观众的房间里**。时钟读的是墙上的表，而隐藏标签页的 rAF 被浏览器 throttled 成一秒一格 —— 学习者切出去两分钟再回来，看到的可能是一堂已经演完的课，旁白还对着空房间念完了全程。所以 `visibilitychange` 一到就把时钟停住，回到前台自己接上；学习者自己按下的暂停不会被我们替他续上，`tick()` 也拒绝在 `playing=false` 时推进（那一格迟到的回调不是走钟的理由）。

## 导演能说什么（19 个动词）

- 编排：`stage_script`（一次调用铺好整场骨架：每拍说什么、多长、镜头怎么动、道具落在哪）
- 立道具：`build` `draw`（导演自己给 svg/html/scene3d）`move` `discard` `recall` `link` `fetch_prop`
- 交给美工：`paint`（只描述"它是什么、要表达什么关系"，图形由第二个模型生成，逐笔长在舞台上；画坏了就把这个刚立起来的空框撤掉）
- 观看：`camera`（fit / focus / pan / zoom / track，特写取道具自身的一个部位分数点）`transition`（dissolve / wipe / match-cut / split）`highlight`（pulse / outline / dim-rest / shake）`motion`
- 时钟：`narrate`（三种上屏方式：caption 底下一行字 / verse 整句落在板心 / voice 只出声不上字）`beat`
- 回路：`ask_learner`（带 `concept`，答完才继续，答案作为工具结果回来，导演据此分叉）`pause_for`
- 状态：`note_progress` `stage_state`

道具的 SVG 源码默认**不在模型上下文里**，要看就 `fetch_prop`。历史本身也按预算折回：`agent/budget.ts` 把超出窗口的**整组**旧轮次里的长字符串换成一句指针（工具调用和它的结果永不拆开，最近 6 组一个字节都不动），折过一次的字节不再变动 —— 那是服务商前缀缓存能活下来的条件。

## 两个角色

导演负责编排，美工（`PAINTER`）只画图不说话，产出一个内联 `<svg>`。你会看到它在舞台上逐笔长出来。两条路径共用同一个 `Teacher.ask()`，所以服务商限流的退避对两个角色一视同仁 —— 美工失败不再是"把错误文本回给导演、让他再烧一次限流窗口"。

美工的契约是**透明背景**：舞台本身就是一块深色黑板（带底色和网格），道具是直接画在它上面的，所以不许交满幅矩形、不许写 `background`。契约之外还有兜底：`StageView` 在注入 shadow root 之后，把 svg 的**第一个直接子 `<rect>`** 剥掉 —— 条件是它不透明（含 SVG 默认的"无 fill = 黑"）、无边框、起点在画面角上且盖住 90% 以上 viewBox。带 `fill-opacity`、留了边距的托底块、`fill="none"` 的边框框都原样保留。

取景有下限：部位特写（`camera` 的 `at`/`span`，默认 span 0.45）、`zoom`、`focus`、单道具 `fit` 都不再把画面框收进 **450** 世界单位以内（`MIN_CLOSEUP_W`）—— 美工的最小字号是 28 单位，450 单位约 3.5 倍放大，字仍然是一个字；旧下限 260 是六倍多，标签被吹成一面墙。

## 3D 是数据，不是代码

`scene3d` 是一份声明式图元表（box / sphere / cylinder / cone / torus / plane / line / arrow + camera / spin / grid / axes），由 `engine/Scene3D.tsx` 里我们自己的解释器编译成 three.js 对象。入参过白名单：形状枚举、fov 夹在 10..120、颜色必须是 `#hex`、图元数量截到 64、和板同色的 `background` 被丢掉（那是从 3D 窗里偷渡进来的第二块板）。

白名单住在 `engine/guard.ts`，不在导演工具里 —— 因为能站到解释器面前的有两条路：一次工具调用，和**别人录的一段带**（`#s=` 链接、导入）。以前只有第一条有门。

一支 3D 道具是**二维板上的一扇内嵌窗**：它仍然持有一个二维 `box`，平板摄影机负责框它、平移它，三维相机只往窗里看。两把相机分层，永不打架。所以 3D 能进日志、能分享、能重放。

`spin` 是 t 的纯函数（可重放）；`interactive` 的拖动角度是**学习者状态，不入带** —— 遥测条会明说这一点。

## 没有 JS 沙箱（明确的取舍）

模型只能交 markup，不能交代码。markup 过 `DOMPurify`（`StageView.tsx` 的 `MARKUP`）：MathML 标签整族关掉（公式由舞台自己用 KaTeX 排，见下）、`iframe` / `object` / `embed` / `form` / 表单控件 / `<a>` 一律剥掉、`srcdoc` / `srcset` / `action` / `target` 这类属性不进白名单、data-* 不开 —— 一个道具是一张画，板上没有任何东西该跳走。道具在 shadow root 里渲染（作用域隔离，模型写的 CSS 动不到外壳），CSS 另走一遍 `DOMPurify` 只留文本，防字面 `</style>` 越狱。这条路的入口是一个 `#s=` 分享链接：它可以来自任何人，所以这是信任边界，不只是"模型不太可能这么写"。

代价：板上的东西不会自己跑逻辑。收益：日志可信、可重放、可分享，且不用担心任意代码执行。

"日志可信"有一句前提：**可信是因为它过了门**。分享链接把整段日志 deflate 进 URL，重放时没有任何模型在场，所以 `#s=` 里的那些 op 也是输入。门在 `engine/log.ts` 的 `append()` 和 `restore()` 上，两条路共用 `guardOp()`：坏字段被默认，不被整卷拒绝 —— 磁带是别人上的一节课，点链接的人没有犯错。

门管两件事。类型：枚举回到解释器认得的值，`answer` 也是一个 op 而不是特例（它的 `gate` 必须是个数，否则那句回答不属于任何题卡，而那句话的契约是 `said: string | null`）。**量级**：时长封顶 120 秒，因为整场的长度就是时间轴的 `max` —— 一句 `duration: 1e18` 以前把一堂课变成 317 年；坐标封顶 ±20 万（板是 1600×900，这是两个数量级的手摆余地），因为相机拿它做浮点算术；台词、名字、markup 各有长度上限，二十万字的旁白按 `speechMs` 折算是 10.7 小时的舞台时间，2.8MB 的 `<svg>` 要在 DOMPurify 里整棵解析一遍。3D 用的是它自己那套单位（`size: 1e9` 不是画不出来，是把 far plane 拖到 6e10 上，此后整个窗口没有深度）。`camera` 的 `center` 和 `at` 长得一样、意思相反：前者是平面上的点，后者是目标框里的比例 —— 门以前把两者都当比例夹进 0..1，于是一刀"pan 到 x=2400 那块板"落到了原点那一角。

解释器自己也不许是二次的，也不许把栈压垮：`unionBox` 以前写成 `Math.min(...boxes)`，而展开是**栈上的参数表** —— 十三万个名字不是一个难看的大框，是 `RangeError`，板子根本不加载。一板的地皮以前每格道具重测一遍整板（二十万格实测两分多钟），`answer` 以前从头扫一遍卡表，`here` 以前每格道具把身后的带读到底（四万个占位符实测 7.4 秒）。那都不是"慢"，是标签页冻住 —— 而一条长带是合法输入，门只能封顶每个字段，封不了整卷有多少条。

观众那一头也不许。上面那些量完之后，同样的账还留在 React 里两处：抽屉的指令日志每一帧把整卷重排一遍 —— 而且**抽屉关着也照排**，因为"关"只是一个 CSS transform；节拍条每一帧把每一拍重排一遍。同一套探针在修前修后各跑一遍（jsdom，min-of-5，时钟在同一拍里走一帧）：节拍条 400 / 2000 / 5000 / 20000 段是 10.7 / 49.9 / 132.6 / 647.8ms，修完 0.4 / 0.1 / 0.08 / 0.08ms；日志 2000 / 5000 / 20000 行是 81.9 / 171.2 / 689.0ms，修完 0.9 / 1.4 / 2.0ms —— 一秒钟六十帧，一节课只要够长就一直在付这笔钱。修法是把两样东西分开：**这卷带子**只在有人演出的时候动，**时钟**每帧都在动 —— 于是日志记住的是排好的那批元素（引用不变，React 逐棵子树跳过），节拍条用二分找出现在站着的那一拍，只重画亮起和熄灭的那两段。剩下那点钱是 App 每帧把那个数组按引用比对一遍，跟重排整卷不是一回事。`view.test.ts` 断的是**重画次数**而不是毫秒：共享 CI 的噪声比省下来的那些毫秒大，而"一段在 render 里读了什么"就是它重画过的指纹。

同一句话还欠着解释器自己那一半。React 修完之后，带子的长度仍然从每一帧进来：一帧把整张 cue 表按下标读**六遍** —— `render` 筛两遍（旁白、幕布）、`visibleProps` 筛两遍（强调、运动）、`cameraAt` 再 `filter` 一遍挑出镜头轨（顺带每帧拷出一个新数组）、`cutAt` 用 `for..of` 走完整表一遍。这还只是录像重放；现场直播时 `owedAt` 那一刀也要扫整表找站着的那一拍。每一格道具再把自己的外观表 `filter` 复制一遍。卡片那头是 `cardAt` 每帧 `gates.filter` 拷一份卡表，而且一张没人答过的旧卡之后，每帧把它前面整段已答的卡重扫一遍。同一支探针换个计数器 —— 数的是**渲染一帧在 cue 表上路过的格子数**（给 `Compiled.cues` 套一层 Proxy，按下标读一次算一格）：2 000 / 8 000 / 32 000 / 128 000 条 cue 的表，修前一帧路过 12 000 / 48 000 / 192 000 / 768 000 格（正好 6 倍），带子长 16 倍路过也长 16 倍；同批规模的 `seek` 是 0.27 / 1.34 / 2.98 / 11.86ms，而一帧的预算是 16.7ms。修完那一帧路过 0 格、`seek` 3.93ms —— 那几毫秒是"这一刻站着的道具"，与带子多长无关。

修法是 `engine/frame.ts` 的 `TapeIndex`：带子重新解释的那一刻（每有人落下新 op，或某一拍被剪断重排）顺手算一次位置索引，一帧只问二分。靠两件"带子已排序"本该付的价钱 —— `t` 单调不减所以能二分；叠层的 cue 会互相盖住（同一拍里两刀 camera 的 `t` 相同、`end` 不同），`end` 本身不单调、不能按它二分，但它的**前缀最大值**单调不减，于是"还在跑的"恰好落在 `[第一条前缀最大 > t, 第一条 t > t)` 这一小段里。窄表按 kind 分好（镜头与幕布、占时钟的、旁白、换场、运动按道具），卡片另有一张开卡表 —— `said` 只随带子变（他的回答本身就是一条 op），所以它是带子的函数，可以在这里算一次。索引不重新解释任何东西：拿的就是 `compile()` 的那份 `Compiled`，所以"索引算错了"和"解释器算错了"不会混成一处。`frame.test.ts` 钉三层：改前的形状（每一刀在代表性那一刻的答案，改完原样绿）、价钱（Proxy 数出来的格子数与带子长无关）、是非（索引和"整条带子扫一遍"在同一批刻点上逐条相等）。

同一卷带子还欠一件事：撤下不是一个**状态**，是一串**时刻**。道具以前身上挂一个 `discardedAt` 数，`discard` 写下它，一次重画或 `recall` 又把它清空 —— 于是三条账都读错。`撤下 → 重新落下` 之后倒带回到两者之间，观众看见一件早就被他撤掉的东西还在台上，因为那个数已经被后一次落笔抹掉了；`撤下 → 重新落下 → 再撤下` 更只剩最后那一刀，中间"已经撤了、还没重画"那一段根本没有记录；而 `visibleName` 压根不看这个字段，于是它和 `visibleProps` 对同一个名字有两种说法 —— 上一件明确记下"那是下一件"，这一件就是那件。后果不是难看：`blindCamera` 靠 `visibleName` 决定要不要告诉导演"镜头点名的东西观众看不见"，它说看得见，那一刀就不动，也不解释，模型把这份静默读成"动过了"。

改法是把词汇里本来就在的那个东西给道具的外观：一次 `revision` 是一段窗口 `[t, off)`，和 `Cue` 的 `t`/`end` 同一件东西。`markOff` 给**此刻站着的那一次外观**盖上结束时刻（已经收过就不动 —— 一个名字不会因为被多念一刀就更消失一次），`layRevision` 在下一次落笔时把上一段收在这一刻，所以同一个道具的窗口**铺满**时间线：不重叠、按 `t` 递增，下一件才二分得动。三条边界都得当场决定，都不是顺手：`patch` 填占位符时新格**继承**旧格的时刻，那是同一段窗口而不是新的一格（于是窗口必须带着自己那个 `off` —— 美工迟到的那一笔落在撤下之后，不许让一件导演已经撤掉的东西复活，图没丢，它就在这段收掉的窗口里，`recall` 带的正是它）；`recall` 那份 `{...prev}` 必须抹掉 `off`，原样抄过来就是"带回来的东西一上台就已经是撤着的"，道具闪一下消失而带子上没有第二刀 discard。`agentSnapshot` 以前读 `revisions.at(-1)`（带子尽头），现在读播放头站着的那一格：学习者倒回三分钟前、导演在那一刻接一句，快照会把还没落下的图报给他，他照着"台上明明有的东西"发一刀 fit，画面不动，还以为是自己的镜头写错了 —— 报的板名也一并从 `p.scene` 改成 `rev.scene`，道具后来挪去哪了不是这一刻的台。

`offstage.test.ts` 按仓库的老手艺钉：把**改前那条规则**重放一份当参照（不是从新结构反推 —— 旧写法里落笔会清空那个数，"撤下 → 重画"之后它是"没有"而不是"某个时刻"），在随机带上逐刻双向对账，差异只许有一个方向（旧写法多算一个站在台上的人），而且必须真的量到。两处探针自己先红过：刻点只取窗口**边缘**量不到任何东西 —— 旧写法撒谎的那一段正是"已经撤下、还没重画"的**内部**，那里没有一个时刻是某段窗口的边缘，所以要补相邻边缘的中点；乘同余的 `seed * 1103515245` 在 float64 里超过 2^53 丢精度，`& 0x7fffffff` 于是拿到同一个数，一整批带子一条 `discard` 都没有，换成 `Math.imul` 才真的随机。那条 `expect(lies.length).toBeGreaterThan(0)` 红过一次，这条对账才不是空转的门。

窗口铺满之后，上一件剩下的那几毫秒才有另一件的样子：`visibleProps`、`visibleName`、`agentSnapshot`、`owedAt` 四个读者过去每帧都把**整张道具表**走一遍，逐格倒着找"这一刻站着的那一次外观"，一帧的价钱是"这堂课一共有过几个道具"，而不是"此刻台上有几个"。同一支探针换个数着的表（给 `Compiled.props` 和每格 `revisions` 各套一层 Proxy，Map 的方法要绑回真表，否则是 incompatible receiver）：500 / 8000 格道具的课，一帧路过 **1510 / 24158** 格、走表 **2** 遍（画名单一遍、`owedAt` 再一遍，后者只在直播时付），60 次 `seek` 平均 0.67–0.92 / 11.1–11.5ms —— 又贴到一帧 16.7ms 的预算上了。走的那一遍里还包括观众早就看不见的：被换场扫走的、已经撤下的、还站在别的板上的。

修法是 `engine/standing.ts` 的 `StandingIndex`：把窗口两端合成**一条**排好的事件流（落下和收走同一列，同一刻先收旧的再落新的，那正是 `[t, off)` 左闭右开说的次序），一个游标答"时刻 `<= t` 的全 apply 完"。时钟一帧走十几毫秒，所以一帧越过的通常一个都没有；倒带不是重扫整卷，是把走过的那几条逐条退回去（`take`/`put` 是同一对操作的两个方向，倒着走就按原样反着 apply）。换场那半条规则在这里折成两次二分：每块板的外观按 `(t, rank)` 排成一列，"这一刀之后才落笔、却站在别的板上"的那些是每列的一段**尾巴**；板再由"这块板上最晚一次落笔"排成一条升序表，所以一板上的旧东西再多也进不了这一帧。名单按**落下次序**排（和过去直接走那张表一样 —— 层叠不许因为换了读法就改），只在台上真的变了东西时重排一次，一帧拿的是同一个数组引用。欠画那一遍要的"这一拍落了几格"由 `laidIn` 二分出来，不再问一遍整张表。

`standing.test.ts` 钉的是同一套三层。价钱那一层先做**反向验**：语义不动、只把读法改回线性（`visibleProps`、`owedAt` 各自退回"走一遍整张表"，答案逐刻仍然相同），跑全套各红一条，红的都只有价钱那一条 —— 说明它数的是钱不是行为。索引自己有四处变异：丢掉板的尾巴（红观众名单 + 「换场扫不走自己板上的东西」）、同一刻改成先落后收（红观众名单 + 「同一刻换板重画」）、`laidIn` 不筛窗口（红「这一拍落的笔」）、分板用 `prop.scene` 代替 `rev.scene`（红观众名单）。把整条换场规则关掉（`visible` 无视 `cut`）红八条，跨过三个文件，包括 `stage.test.ts` 那几条形状和上一件的账。**真正漏空的一处是删掉 `owedAt` 里那句 `swept` 筛子：那时 182 条一条都不红。** 那一格不在观众名单上（幕布已经盖过去了），却仍然被数进"这一拍还欠几幅画"，而这一件之前它没有自己的名字 —— 走整张表那一遍逐格问的是同一条规则，换成二分之后它成了一句独立的话，于是可以整句消失。补的两条（`paint-debt.test.ts` 的「换场扫走的那一格不欠时钟任何东西」）钉在**时钟**上而不是名单上，因为这半条错法只有时钟表演得出来：观众已经不在那块板上，时钟却为一块他们再也看不见的空框停死在这一拍，字幕栏写"时钟等美工"，等的是永远不会落地的那一幅；前一条（幕布还没盖过去，时钟确实该停）是它的门，盯的是把这句反过来弄坏那条路 —— 实测"站着的全都算被扫走"（`if (true) continue`）只红前一条，"整句删掉"只红后一条，两条各守一个方向。刻点那一头照上一件的教训办：`marks()` 除了落笔与收笔，还要放进每一刀的 `flip`（幕布盖住整块板的那一刻）和相邻边缘的中点 —— 换场那半条恰好只在 `flip` 那一刻翻脸，只问边缘量不到。

量完：同一支探针，一帧在道具表和外观表上路过 **0 格**、走表 **0** 遍，60 次 `seek` 平均 0.06–0.18 / 0.73–1.04ms（改前 0.67–0.92 / 11.1–11.5ms）；建的价钱一次线性的（每个道具走一次、每格外观点一次），带子长 16 倍之后一帧多走的格子是 0。全套 168 → 184 条绿，原有断言仍然一条没改。

`compile.test.ts` 用规模测试把这些钉住了：一条长带付一次线性的价钱，界内那一刀仍然算数（占位符排在镜头之前就得跟着镜头走）。

## 公式是排版的，不是手画的

道具 markup 里任何带 `class="tex"` 的元素，它的文本内容会被 KaTeX 排成 **MathML**，浏览器自己完成排版。契约就一条：给一个 `<text>` 挂上 `class="tex"`，内容写 LaTeX（`<text class="tex" x="40" y="90" font-size="48" fill="#fde68a">\vec r=\vec a+\vec b</text>`）—— `y` 是基线，窗口的位置和宽高由舞台算。模型自己写的 `<foreignObject>` 不算入口：DOMPurify 把它列进 svg 禁用表（那是 mutation-XSS 的门），净化器会把这扇窗连同里面的公式一起删掉，所以只有 `class="tex"` 这一条路。

只取 `output: 'mathml'`：不引 KaTeX 的 CSS，不搬它的 woff2，不改写任何 `url()`。日志里存的仍是那串 LaTeX 源码 —— 所以公式进得了分享链接、重放和重排，而且它跟着画面一起被特写放大，和一条笔画同样缩放。

代价：MathML 的渲染细节由浏览器决定（Chrome/Safari/Firefox 原生，旧浏览器会退化成一行普通文本）。这是换来的：真分数、根号、下标、矩阵，零样式注入。

## 哪些轮子是借的，哪些是自己造的

借的：`@earendil-works/pi-ai`（模型传输、流式、凭据、faux provider）、`three`（3D 图形栈）、浏览器自己的 SVG/HTML/CSS 引擎（2D 表达面就是标准 DOM，没有再包一层）、`speechSynthesis`（配音）、`katex`（只做 LaTeX→MathML 的字符串转换，排版交给浏览器，见上）。

自己造的只有三样，且都有理由：**op 日志 + 解释器**（没有任何库把"只增不删的指令带"当唯一真相，从而让分享、重放、重排都是副产品）；**时钟归旁白**（GSAP / Motion Canvas 这类 tween 库要夺走时间的所有权，而这里 `t` 必须是纯函数，倒带和分享才可能字节一致）；**二维板 + 摄影机**（Pixi/Konva 这类保留模式画布吃的是解析好的图元，接不住"模型边吐 markup 边长出来"的磁带头，也没有 shadow root 的作用域隔离）。

结论：表达层没有重造轮子 —— 它就是 DOM；重造的是**时间的所有权**，那是这个产品区别于"一段渲染好的视频"的地方。

## 验证分三层

别拿 fixture 的绿灯当服务商链路的绿灯。

1. **排练模式（faux）**：只证明"我自己的代码自洽"。
2. **mock OpenAI 兼容服务**（`scripts/mock-openai.mjs`，自己的 Node 进程）：验传输适配器形状。开关：`MOCK_PORT`、`MOCK_HOLD=<ms>`（拖住首拍以量冷启动窗口）、`MOCK_429=<role>:<N>`（该角色前 N 次返回真 HTTP 429）、话题里写 `MOCK-TRUNC-N`（前 N 次导演调用只回 reasoning + `finish_reason=length`）。计数器是进程全局的，换场景要重启 mock。
3. **真实服务商**：端到端跑完整堂课才算证。

双端对账是唯一免疫观察通道污染的办法：mock 的 stdout 记"发出了几条什么形状"，页面 transcript 记"收到几条 / 推了几条 nudge"，两边对上才算。

服务商限流通常是 **tokens-per-minute**：单场长课能吃到十几万 tokens。测完一轮要算代价，别为验证反复开真课。

## 已知边界

- 密钥在 localStorage，DevTools 可见（见上）。
- 3D 的拖动角度不进分享链接（设计决定：那是学习者状态，不是演出）。
- `build` 的 `here`（"落在当前镜头正中"）由 `compile.test.ts` 钉住了语义（同帧让位、跟着本拍的 pan 走、命名别的板就落到那块板的地皮上），但真机上仍只有 mock/faux 触发过 —— 真实模型每次都自己报了坐标。
- `inkBox` 只测平移和缩放两种变换，遇到 rotate/skew 就明说"这 estimate 不可信"并退回声明的 box —— 宁可瞄框，不瞄一个算错的墨迹位置。
- `guardOp` 兜解释器会算错的**量**（数字、枚举、时长、坐标、字符串与 markup 的长度、数量上限），不兜整卷的总量：每帧的可见道具数、DOM 节点数不在门上封顶 —— 那要封顶得先决定"一堂课能有多少道具"，那是编课的问题。它也不判断语义：一段把三板堆在同一个坐标上的带照样能过门。
