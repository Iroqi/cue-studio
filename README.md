# Cue Studio

一个 LLM 驱动的教师agent。它的媒介不是幻灯片，是一块无界的二维舞台平面（backstage）和一架摄影机 —— 知识被**演**出来，不是被列出来。

## 为什么它不是一个 artifact

常见的 AI artifact 是编译型的：模型一次生成一个成品。这里相反。

模型每次调用只发出一条 `op`（"说这句话，12 秒"、"把这支向量放到板上"、"镜头推到箭头尖"），追加进一条**只增不删的日志**。解释器把日志演化成舞台：道具表、时钟、镜头轨迹、门（gate）。成品不存在，只有过程 —— 这是"解释型"和"编译型"的区别。

推论：一堂课 = 一段磁带。所以分享（日志 deflate 后塞进 URL hash）、重放、从任意一拍截断重排，全都是日志的副产品，没有一个是单独实现的功能。

## 词汇

代码、提示词、UI 用的是同一套词，没有第二套命名。

| 词 | 是什么 |
| --- | --- |
| backstage | 无界二维平面。一场戏约 1600×900 单位，场景之间相隔 2000~3000。**一块被命名过的板就有位置**，哪怕它还是空的（`BOARD_SPACING = 2400`，按演出走上它的顺序排开）—— 否则切过去的那一刀没有地方可去 |
| prop 道具 | 平面上有身份的对象。**id 跨场景持续** —— 第三幕那个箭头仍然是第一幕那一个 |
| revision | 同一道具的一次外观变更（画错了重画、补细节），带自己的 `box` 和一段窗口 `[t, off)` —— `off` 是被 `discard` 撤下的那一刻，`undefined` 就是到带子尽头还站着 |
| cue | 一次工具调用 = 一个 cue，落在舞台时间轴上 |
| beat | 刻意的静默，让画面自己站住 |
| gate | 停时钟等学习者的地方：`ask_learner` / `pause_for` |
| tape | 日志本身，可导出、可分享、可重演 |

学习者也是台上的人，所以他说的话也在磁带上：`answer` 是新加的一个 op，由舞台在他回答的那一刻落下，只记内容和他答的是哪张卡，**不占时钟**。这一条把三件事变成副产品 —— 分享出去的录像带着他答错的那句话（那是一堂课里最值钱的上下文）；重放知道哪些卡已经答过；剪断某一拍重排时，他的回答跟着那一拍一起回去，因为那是它唯一存在的地方。于是"已答/未答"不再是运行时另外记的一本账，而是从带上读出来的事实。

配套的一条决定：**录像不再向看的人重新提问。** `live=false` 时 `currentGate()` 恒为 null，进度条一路走到底不会卡在别人的题上 —— 点开链接的人是来看的。想真的上这门课，接着说一句，板子从那一刻起变回 live，下一张卡就停在他面前。

## 时间规则（最要紧的一条设计）

只有 `narrate` / `beat` / `transition` **占时钟**。`camera`、`highlight`、`motion` 是叠在旁白之上的覆盖层，不推进时间。

覆盖层到点就走，不留痕：`highlight` 的四种里，`dim-rest` 是唯一打在**板子**而不是打在道具上的强调 —— 被点名的那块保住亮度，其余的退到后面（类名挂在 `.world` 上，因为"其余的"没法写进一条道具选择器里）。

所以"这一段讲多久"由旁白决定，运镜不能把课拖长。`motion` 的位移是**舞台时间的纯函数**（oscillate / approach / orbit / iterate / flow）—— cue 一结束道具回到它的锚点，倒带回去它也在那个位置。

道具的坐标是它的**锚点**，不是某一帧。想让一个东西自己动，是发一个 motion cue，不是一帧帧重画。

第二条规则：**时钟不许跑在画面前面**。首次演出时，只要镜头框住一个还没有任何图形的空框、而它的 `paint` 正在进行，`tick()` 就不推进 `t`（`playing` 保持 true，rAF 继续转，所以美工一交图它自己接上走）。美工开始流式吐线的那一刻就放行 —— 3b1b 的节奏是"边画边讲"，毛病出在"讲完了画还没出现"。重放时 `live=false`，画面早就在日志里，不需要等。

第三条规则，和第二条同一条：**也不许跑在没有观众的房间里**。时钟读的是墙上的表，而隐藏标签页的 rAF 被浏览器 throttled 成一秒一格 —— 学习者切出去两分钟再回来，看到的可能是一堂已经演完的课，旁白还对着空房间念完了全程。所以 `visibilitychange` 一到就把时钟停住，回到前台自己接上；学习者自己按下的暂停不会被我们替他续上，`tick()` 也拒绝在 `playing=false` 时推进（那一格迟到的回调不是走钟的理由）。

## 导演能说什么（19 个动词）

- 编排：`stage_script`（一次调用铺好整场骨架：每拍说什么、多长、镜头怎么动、道具落在哪）
- 立道具：`build` `draw`（导演自己给 svg/html/scene3d）`move` `discard` `recall` `link` `fetch_prop`
- 交给美工：`paint`（只描述"它是什么、要表达什么关系"，图形由第二个模型生成，逐笔长在舞台上；画坏了就把这个刚立起来的空框撤掉）
- 观看：`camera`（fit / focus / pan / zoom / track，特写取道具自身的一个部位分数点）`transition`（dissolve / wipe / match-cut / split）`highlight`（pulse / outline / dim-rest / shake）`motion`
- 时钟：`narrate`（三种上屏方式：caption 底下一行字 / verse 整句落在板心 / voice 只出声不上字）`beat`
- 回路：`ask_learner`（带 `concept`，答完才继续，答案作为工具结果回来，导演据此分叉）`pause_for`
- 状态：`note_progress` `stage_state`

道具的 SVG 源码默认**不在模型上下文里**，要看就 `fetch_prop`。历史本身也按预算折回：`agent/budget.ts` 把超出窗口的**整组**旧轮次里的长字符串换成一句指针（工具调用和它的结果永不拆开，最近 6 组一个字节都不动），折过一次的字节不再变动 —— 那是服务商前缀缓存能活下来的条件。

## 两个角色

导演负责编排，美工（`PAINTER`）只画图不说话，产出一个内联 `<svg>`。你会看到它在舞台上逐笔长出来。两条路径共用同一个 `Teacher.ask()`，所以服务商限流的退避对两个角色一视同仁 —— 美工失败不再是"把错误文本回给导演、让他再烧一次限流窗口"。

美工的契约是**透明背景**：舞台本身就是一块深色黑板（带底色和网格），道具是直接画在它上面的，所以不许交满幅矩形、不许写 `background`。契约之外还有兜底：`StageView` 在注入 shadow root 之后，把 svg 的**第一个直接子 `<rect>`** 剥掉 —— 条件是它不透明（含 SVG 默认的"无 fill = 黑"）、无边框、起点在画面角上且盖住 90% 以上 viewBox。带 `fill-opacity`、留了边距的托底块、`fill="none"` 的边框框都原样保留。

取景有下限：部位特写（`camera` 的 `at`/`span`，默认 span 0.45）、`zoom`、`focus`、单道具 `fit` 都不再把画面框收进 **450** 世界单位以内（`MIN_CLOSEUP_W`）—— 美工的最小字号是 28 单位，450 单位约 3.5 倍放大，字仍然是一个字；旧下限 260 是六倍多，标签被吹成一面墙。

## 3D 是数据，不是代码

`scene3d` 是一份声明式图元表（box / sphere / cylinder / cone / torus / plane / line / arrow + camera / spin / grid / axes），由 `engine/Scene3D.tsx` 里我们自己的解释器编译成 three.js 对象。入参过白名单：形状枚举、fov 夹在 10..120、颜色必须是 `#hex`、图元数量截到 64、和板同色的 `background` 被丢掉（那是从 3D 窗里偷渡进来的第二块板）。

白名单住在 `engine/guard.ts`，不在导演工具里 —— 因为能站到解释器面前的有两条路：一次工具调用，和**别人录的一段带**（`#s=` 链接、导入）。以前只有第一条有门。

一支 3D 道具是**二维板上的一扇内嵌窗**：它仍然持有一个二维 `box`，平板摄影机负责框它、平移它，三维相机只往窗里看。两把相机分层，永不打架。所以 3D 能进日志、能分享、能重放。

`spin` 是 t 的纯函数（可重放）；`interactive` 的拖动角度是**学习者状态，不入带** —— 遥测条会明说这一点。

## 没有 JS 沙箱（明确的取舍）

模型只能交 markup，不能交代码。markup 过 `DOMPurify`（`StageView.tsx` 的 `MARKUP`）：MathML 标签整族关掉（公式由舞台自己用 KaTeX 排，见下）、`iframe` / `object` / `embed` / `form` / 表单控件 / `<a>` 一律剥掉、`srcdoc` / `srcset` / `action` / `target` 这类属性不进白名单、data-* 不开 —— 一个道具是一张画，板上没有任何东西该跳走。道具在 shadow root 里渲染（作用域隔离，模型写的 CSS 动不到外壳），CSS 另走一遍 `DOMPurify` 只留文本，防字面 `</style>` 越狱。这条路的入口是一个 `#s=` 分享链接：它可以来自任何人，所以这是信任边界，不只是"模型不太可能这么写"。

代价：板上的东西不会自己跑逻辑。收益：日志可信、可重放、可分享，且不用担心任意代码执行。

"日志可信"有一句前提：**可信是因为它过了门**。分享链接把整段日志 deflate 进 URL，重放时没有任何模型在场，所以 `#s=` 里的那些 op 也是输入。门在 `engine/log.ts` 的 `append()` 和 `restore()` 上，两条路共用 `guardOp()`：坏字段被默认，不被整卷拒绝 —— 磁带是别人上的一节课，点链接的人没有犯错。门管的是 op **自己说了什么**；它有一段时间没有管 op **坐在哪儿**（`seq`/`turn`/`track`/`group`），见下面"账本上的号也要过门"。

门管两件事。类型：枚举回到解释器认得的值，`answer` 也是一个 op 而不是特例（它的 `gate` 必须是个数，否则那句回答不属于任何题卡，而那句话的契约是 `said: string | null`）。**量级**：时长封顶 120 秒，因为整场的长度就是时间轴的 `max` —— 一句 `duration: 1e18` 以前把一堂课变成 317 年；坐标封顶 ±20 万（板是 1600×900，这是两个数量级的手摆余地），因为相机拿它做浮点算术；台词、名字、markup 各有长度上限，二十万字的旁白按 `speechMs` 折算是 10.7 小时的舞台时间，2.8MB 的 `<svg>` 要在 DOMPurify 里整棵解析一遍。3D 用的是它自己那套单位（`size: 1e9` 不是画不出来，是把 far plane 拖到 6e10 上，此后整个窗口没有深度）。`camera` 的 `center` 和 `at` 长得一样、意思相反：前者是平面上的点，后者是目标框里的比例 —— 门以前把两者都当比例夹进 0..1，于是一刀"pan 到 x=2400 那块板"落到了原点那一角。

解释器自己也不许是二次的，也不许把栈压垮：`unionBox` 以前写成 `Math.min(...boxes)`，而展开是**栈上的参数表** —— 十三万个名字不是一个难看的大框，是 `RangeError`，板子根本不加载。一板的地皮以前每格道具重测一遍整板（二十万格实测两分多钟），`answer` 以前从头扫一遍卡表，`here` 以前每格道具把身后的带读到底（四万个占位符实测 7.4 秒）。那都不是"慢"，是标签页冻住 —— 而一条长带是合法输入，门只能封顶每个字段，封不了整卷有多少条。

观众那一头也不许。上面那些量完之后，同样的账还留在 React 里两处：抽屉的指令日志每一帧把整卷重排一遍 —— 而且**抽屉关着也照排**，因为"关"只是一个 CSS transform；节拍条每一帧把每一拍重排一遍。同一套探针在修前修后各跑一遍（jsdom，min-of-5，时钟在同一拍里走一帧）：节拍条 400 / 2000 / 5000 / 20000 段是 10.7 / 49.9 / 132.6 / 647.8ms，修完 0.4 / 0.1 / 0.08 / 0.08ms；日志 2000 / 5000 / 20000 行是 81.9 / 171.2 / 689.0ms，修完 0.9 / 1.4 / 2.0ms —— 一秒钟六十帧，一节课只要够长就一直在付这笔钱。修法是把两样东西分开：**这卷带子**只在有人演出的时候动，**时钟**每帧都在动 —— 于是日志记住的是排好的那批元素（引用不变，React 逐棵子树跳过），节拍条用二分找出现在站着的那一拍，只重画亮起和熄灭的那两段。剩下那点钱是 App 每帧把那个数组按引用比对一遍，跟重排整卷不是一回事。`view.test.ts` 断的是**重画次数**而不是毫秒：共享 CI 的噪声比省下来的那些毫秒大，而"一段在 render 里读了什么"就是它重画过的指纹。

同一句话还欠着解释器自己那一半。React 修完之后，带子的长度仍然从每一帧进来：一帧把整张 cue 表按下标读**六遍** —— `render` 筛两遍（旁白、幕布）、`visibleProps` 筛两遍（强调、运动）、`cameraAt` 再 `filter` 一遍挑出镜头轨（顺带每帧拷出一个新数组）、`cutAt` 用 `for..of` 走完整表一遍。这还只是录像重放；现场直播时 `owedAt` 那一刀也要扫整表找站着的那一拍。每一格道具再把自己的外观表 `filter` 复制一遍。卡片那头是 `cardAt` 每帧 `gates.filter` 拷一份卡表，而且一张没人答过的旧卡之后，每帧把它前面整段已答的卡重扫一遍。同一支探针换个计数器 —— 数的是**渲染一帧在 cue 表上路过的格子数**（给 `Compiled.cues` 套一层 Proxy，按下标读一次算一格）：2 000 / 8 000 / 32 000 / 128 000 条 cue 的表，修前一帧路过 12 000 / 48 000 / 192 000 / 768 000 格（正好 6 倍），带子长 16 倍路过也长 16 倍；同批规模的 `seek` 是 0.27 / 1.34 / 2.98 / 11.86ms，而一帧的预算是 16.7ms。修完那一帧路过 0 格、`seek` 3.93ms —— 那几毫秒是"这一刻站着的道具"，与带子多长无关。

修法是 `engine/frame.ts` 的 `TapeIndex`：带子重新解释的那一刻（每有人落下新 op，或某一拍被剪断重排）顺手算一次位置索引，一帧只问二分。靠两件"带子已排序"本该付的价钱 —— `t` 单调不减所以能二分；叠层的 cue 会互相盖住（同一拍里两刀 camera 的 `t` 相同、`end` 不同），`end` 本身不单调、不能按它二分，但它的**前缀最大值**单调不减，于是"还在跑的"恰好落在 `[第一条前缀最大 > t, 第一条 t > t)` 这一小段里。窄表按 kind 分好（镜头与幕布、占时钟的、旁白、换场、运动按道具），卡片另有一张开卡表 —— `said` 只随带子变（他的回答本身就是一条 op），所以它是带子的函数，可以在这里算一次。索引不重新解释任何东西：拿的就是 `compile()` 的那份 `Compiled`，所以"索引算错了"和"解释器算错了"不会混成一处。`frame.test.ts` 钉三层：改前的形状（每一刀在代表性那一刻的答案，改完原样绿）、价钱（Proxy 数出来的格子数与带子长无关）、是非（索引和"整条带子扫一遍"在同一批刻点上逐条相等）。

那一件漏了强调自己那一格。`highlightsAt` 当时借的是通用那张 running 的窗口，于是**长寿的叠层把整张 cue 表拖进每一帧**：`highlight` 封顶 120 秒（`guard` 的 `MAX_MS`），而"还在跑的"那一头的左边界是前缀最大值 —— 一条 `mark("a", 120_000)` 站在带子上，后面每一帧的左边界都被它顶回表头。同一支探针换个数着的表：同样问"这一刻哪些强调在跑"，2 000 拍那条在 cue 表上路过 2 001 格、120 000 拍那条路过 120 001 格 —— 那一问按的是带子的长度，不是台上有几刀强调。修法不是给通用窗口加聪明办法，而是**再开一条窄表**（`hlT` / `hlCues` / `hlMaxEnd`，强调自己那一对前缀最大值），然后把那张"什么都能问"的通用区间从文件里删掉 —— 留着它，下一头读者就会再借一次。`frame.test.ts` 新增那一节同样三层，整节在改前的代码上跑过（`git checkout 6e5e442 -- src/engine/frame.ts`）：五条里红的正是价钱那一条（0 格对整表），其余四条改前就是绿的 —— 它们是**护栏**，钉的是这一件不许修过头（同一件东西上先后两刀的样式按 `t` 先到先得、走完的那条不许反过来盖住站着的那条、和"整条带子扫一遍"那份参照逐刻相等）。

同一卷带子还欠一件事：撤下不是一个**状态**，是一串**时刻**。道具以前身上挂一个 `discardedAt` 数，`discard` 写下它，一次重画或 `recall` 又把它清空 —— 于是三条账都读错。`撤下 → 重新落下` 之后倒带回到两者之间，观众看见一件早就被他撤掉的东西还在台上，因为那个数已经被后一次落笔抹掉了；`撤下 → 重新落下 → 再撤下` 更只剩最后那一刀，中间"已经撤了、还没重画"那一段根本没有记录；而 `visibleName` 压根不看这个字段，于是它和 `visibleProps` 对同一个名字有两种说法 —— 上一件明确记下"那是下一件"，这一件就是那件。后果不是难看：`blindCamera` 靠 `visibleName` 决定要不要告诉导演"镜头点名的东西观众看不见"，它说看得见，那一刀就不动，也不解释，模型把这份静默读成"动过了"。

改法是把词汇里本来就在的那个东西给道具的外观：一次 `revision` 是一段窗口 `[t, off)`，和 `Cue` 的 `t`/`end` 同一件东西。`markOff` 给**此刻站着的那一次外观**盖上结束时刻（已经收过就不动 —— 一个名字不会因为被多念一刀就更消失一次），`layRevision` 在下一次落笔时把上一段收在这一刻，所以同一个道具的窗口**铺满**时间线：不重叠、按 `t` 递增，下一件才二分得动。三条边界都得当场决定，都不是顺手：`patch` 填占位符时新格**继承**旧格的时刻，那是同一段窗口而不是新的一格（于是窗口必须带着自己那个 `off` —— 美工迟到的那一笔落在撤下之后，不许让一件导演已经撤掉的东西复活，图没丢，它就在这段收掉的窗口里，`recall` 带的正是它）；`recall` 那份 `{...prev}` 必须抹掉 `off`，原样抄过来就是"带回来的东西一上台就已经是撤着的"，道具闪一下消失而带子上没有第二刀 discard。`agentSnapshot` 以前读 `revisions.at(-1)`（带子尽头），现在读播放头站着的那一格：学习者倒回三分钟前、导演在那一刻接一句，快照会把还没落下的图报给他，他照着"台上明明有的东西"发一刀 fit，画面不动，还以为是自己的镜头写错了 —— 报的板名也一并从 `p.scene` 改成 `rev.scene`，道具后来挪去哪了不是这一刻的台。

`offstage.test.ts` 按仓库的老手艺钉：把**改前那条规则**重放一份当参照（不是从新结构反推 —— 旧写法里落笔会清空那个数，"撤下 → 重画"之后它是"没有"而不是"某个时刻"），在随机带上逐刻双向对账，差异只许有一个方向（旧写法多算一个站在台上的人），而且必须真的量到。两处探针自己先红过：刻点只取窗口**边缘**量不到任何东西 —— 旧写法撒谎的那一段正是"已经撤下、还没重画"的**内部**，那里没有一个时刻是某段窗口的边缘，所以要补相邻边缘的中点；乘同余的 `seed * 1103515245` 在 float64 里超过 2^53 丢精度，`& 0x7fffffff` 于是拿到同一个数，一整批带子一条 `discard` 都没有，换成 `Math.imul` 才真的随机。那条 `expect(lies.length).toBeGreaterThan(0)` 红过一次，这条对账才不是空转的门。

窗口铺满之后，上一件剩下的那几毫秒才有另一件的样子：`visibleProps`、`visibleName`、`agentSnapshot`、`owedAt` 四个读者过去每帧都把**整张道具表**走一遍，逐格倒着找"这一刻站着的那一次外观"，一帧的价钱是"这堂课一共有过几个道具"，而不是"此刻台上有几个"。同一支探针换个数着的表（给 `Compiled.props` 和每格 `revisions` 各套一层 Proxy，Map 的方法要绑回真表，否则是 incompatible receiver）：500 / 8000 格道具的课，一帧路过 **1510 / 24158** 格、走表 **2** 遍（画名单一遍、`owedAt` 再一遍，后者只在直播时付），60 次 `seek` 平均 0.67–0.92 / 11.1–11.5ms —— 又贴到一帧 16.7ms 的预算上了。走的那一遍里还包括观众早就看不见的：被换场扫走的、已经撤下的、还站在别的板上的。

修法是 `engine/standing.ts` 的 `StandingIndex`：把窗口两端合成**一条**排好的事件流（落下和收走同一列，同一刻先收旧的再落新的，那正是 `[t, off)` 左闭右开说的次序），一个游标答"时刻 `<= t` 的全 apply 完"。时钟一帧走十几毫秒，所以一帧越过的通常一个都没有；倒带不是重扫整卷，是把走过的那几条逐条退回去（`take`/`put` 是同一对操作的两个方向，倒着走就按原样反着 apply）。换场那半条规则在这里折成两次二分：每块板的外观按 `(t, rank)` 排成一列，"这一刀之后才落笔、却站在别的板上"的那些是每列的一段**尾巴**；板再由"这块板上最晚一次落笔"排成一条升序表，所以一板上的旧东西再多也进不了这一帧。名单按**落下次序**排（和过去直接走那张表一样 —— 层叠不许因为换了读法就改），只在台上真的变了东西时重排一次，一帧拿的是同一个数组引用。欠画那一遍要的"这一拍落了几格"由 `laidIn` 二分出来，不再问一遍整张表。

`standing.test.ts` 钉的是同一套三层。价钱那一层先做**反向验**：语义不动、只把读法改回线性（`visibleProps`、`owedAt` 各自退回"走一遍整张表"，答案逐刻仍然相同），跑全套各红一条，红的都只有价钱那一条 —— 说明它数的是钱不是行为。索引自己有四处变异：丢掉板的尾巴（红观众名单 + 「换场扫不走自己板上的东西」）、同一刻改成先落后收（红观众名单 + 「同一刻换板重画」）、`laidIn` 不筛窗口（红「这一拍落的笔」）、分板用 `prop.scene` 代替 `rev.scene`（红观众名单）。把整条换场规则关掉（`visible` 无视 `cut`）红八条，跨过三个文件，包括 `stage.test.ts` 那几条形状和上一件的账。**真正漏空的一处是删掉 `owedAt` 里那句 `swept` 筛子：那时 182 条一条都不红。** 那一格不在观众名单上（幕布已经盖过去了），却仍然被数进"这一拍还欠几幅画"，而这一件之前它没有自己的名字 —— 走整张表那一遍逐格问的是同一条规则，换成二分之后它成了一句独立的话，于是可以整句消失。补的两条（`paint-debt.test.ts` 的「换场扫走的那一格不欠时钟任何东西」）钉在**时钟**上而不是名单上，因为这半条错法只有时钟表演得出来：观众已经不在那块板上，时钟却为一块他们再也看不见的空框停死在这一拍，字幕栏写"时钟等美工"，等的是永远不会落地的那一幅；前一条（幕布还没盖过去，时钟确实该停）是它的门，盯的是把这句反过来弄坏那条路 —— 实测"站着的全都算被扫走"（`if (true) continue`）只红前一条，"整句删掉"只红后一条，两条各守一个方向。刻点那一头照上一件的教训办：`marks()` 除了落笔与收笔，还要放进每一刀的 `flip`（幕布盖住整块板的那一刻）和相邻边缘的中点 —— 换场那半条恰好只在 `flip` 那一刻翻脸，只问边缘量不到。

量完：同一支探针，一帧在道具表和外观表上路过 **0 格**、走表 **0** 遍，60 次 `seek` 平均 0.06–0.18 / 0.73–1.04ms（改前 0.67–0.92 / 11.1–11.5ms）；建的价钱一次线性的（每个道具走一次、每格外观点一次），带子长 16 倍之后一帧多走的格子是 0。全套 168 → 184 条绿，原有断言仍然一条没改。

镜头是最后一头还在读带子尽头的读者。上一件把"什么站在台上"变成一段窗口，给了每帧四个读者，可解释器算落点那一头没接：`resolve` 拿的是 `revisions[length - 1]` 那一格，问的是"到带子尽头还站着吗"，分板按 `prop.scene`（道具最后被挪去了哪），连收没收笔都不看。于是同一卷带子上有两种说法，而 `blindCamera` 那句"画面这一拍不会动"成了谎话 —— 它按观众那一头判断，镜头按另一头走。改前每一条错法都量过（数字抄在 `camera-moment.test.ts` 旁边）：`focus` 一个刚 `discard` 掉的名字，整帧站到 `{x:5875, y:-46.5625, w:450, h:253.125}`，也就是 x=6000 那件观众早就看不见的东西上，而同一时刻 `visibleName` 当场就是 `false`；`track` 跟同一个名字，画面从 `{x:0,…}` 朝它滑到 `{x:4300,…}`；换场之后点旧板 `甲` 的名，镜头从 `{x:2400,…}` 飞到那块被幕布压住的板上捡回 `{x:-125,…}`；`甲` 上压着两格时框出来的是 `{x:-110, y:-291.25, w:1320, h:742.5}` —— "漏掉第 2 格"和"漏掉整块板"是两种坏法，所以两条都要钉。另外两半只有时钟表演得出来：`discard` 落在 `track` 滑动的中途是常事（叠层不占时钟，下一句可以紧跟着落），那时画面还在往那件刚消失的东西的方向推，实测推到 `x=4585.3…` 而落点是 `4300`；同一卷带子上两刀镜头中间隔一刀 `discard`，第二刀量到的仍然是那格 `w=450` —— 落点是带子上的历史（前一刀不许被后一刀改写），可"这块板现在有什么"必须读此刻。

修法是 `compile.ts` 里的 `CameraGround`：解释器自己那块"观众此刻看得见的地皮"，随带子单调走 —— 落一笔只把那一格并进它那块板，收一笔只能整板重量（并集没有逆运算，留一个偏大的框就是"撤走的东西还在把画面撑大"）。两半规则都要：按 `rev.scene` 站着（这一次外观落在哪块板，不是道具最后挪去哪 —— `standing.ts` 同一句话），并且没被最近那一刀扫走。问法分两种，因为答案本来就不一样：点**脚下**这块板的名量全部（幕布一抬，上一次访问留下的那些就又回到眼前），点**别的**板只量"这一刀 `flip` 之后落下的"（一块被压住的板观众看不见，镜头就该像点一个不存在的名那样不动）；换场的**落点**另问一次全部 —— 那是将要给观众看这块板。走过一刀时 `since` 整份作废，那一头"看得见"换了半条规则。跟读的那一半在时钟上：`StandingIndex.seen` 把 `swept` 折进游标，`ride` 一问就停，不许继续推一件名单里已经没有的名字。顺手挖出另一处二次：`Compiled.scenes` 以前是"每块板把整张道具表走一遍"，一块板一个名字时看不出来（所以旧那条测试是五万格道具、一块板，绿的），板名一多就又是二次的，现在 `groundsAtEnd` 单趟按板并窗口。那一头**故意**留在带子尽头 —— 导演的快照得把被换场扫走的那些也列出来，`recall` 带得回来；镜头那一刻的地皮和带子尽头那一份不许混成一个。

`camera-moment.test.ts` 钉同一套三层，整节在改前的代码上跑过一遍：18 条里 10 条红（形状 6、价钱 3、对账 1），其余 8 条改前就是绿的，它们是**护栏** —— 存在的意义是这一件不许修过头（东西还在的时候镜头照样得走过去，回到一块板照样得把它上面压着的那些一起框住，一块板全空了以后落点只是把脚下那一片放大一点 `{-160,-90,1920,1080}`）。价钱那一头 Proxy 套不到 —— 那笔账在解释器自己造的表上，所以钉的是**对照**：同一卷带子加不加那一刀点名，同一台机器各量一次；省下来的钱不许是答案，所以两侧都补一句"点名仍然站得到那块板"。对账那一头是"从头把带子再读一遍、一个缓存都不许用"那份朴素读法，150 卷随机带子逐刀比 `x/y/w/h`，量到 999 刀镜头、778 刀点了名、253 刀点的是板名、689 刀落点确实和站着不动不同 —— 四个计数器自己钉住探针不许空转。三处坑值得记：按**时刻**读带子在同一毫秒里有两刀时是含糊的，参照必须按位置走；参照框的必须是**墨**（`inkBox`）而不是声明的盒子，否则两边各自错在不同地方；`here` 的落点是相机自己算出来的，把它放进生成器就是拿答案当输入。反向那一条钉的是"那个数确实站在参照说站着的那一格上"—— 参照不是一个自说自话的常量。

量完（同一台机器、同一批带子、各取三次最小值，改前跑两遍各记一个数）：12000 拍、每拍点一次板名那条 **1073 / 1089ms**，同一条把点名去掉是 **23.2 / 21.2ms** —— 点名这件工具本身贵过带子其余部分约 **49 倍**，而"板名可以当镜头目标"是写在 `camera` 说明里的用法，是生产路径不是边角；改后分别 **33.2ms** 与 20.3ms（比值 1.6）。二次那笔账的另一种付法也量：全部堆在一块板上的 1000 → 4000 拍，改前 23.5 → 460.8ms（倍率 19.6），改后 1.9 → 6.1ms（3.3，剩下的是"这块板上有几样"那一项）。导演在台上真正付的是逐拍追加那一笔：3000 拍的带子上追加 20 拍，改前 1017 / 1079ms 对不点名 113 / 117ms（约 9 倍），改后 155ms 对 117ms（1.3）。全套 184 → 202 条绿，原有断言仍然一条没改；tsc / build 干净，oxlint 仍是仓库里那两条旧警告。

镜头之后还有四处读的是带子尽头，而且四处都不是"难看一点"：

`patch`（`draw`、`move` 走的就是它）指一个带上还没有的名字时，解释器**凭空造出一格外观** —— `ensureProp` 先建条目，落点是 `op.box ?? prev?.box ?? VIEWPORT`。实测拼错一个 id，那一格拿到 `{x:0,y:0,w:1600,h:900}`、`partial:false`：那不是空框，是一幅"已经画好的画"，所以时钟**不等它**（`owedAt` 只数空白框欠的画），观众看见一整块盖住板的东西，而带子上没有任何一刀说要它。`link` 只念到名字那一头仓库早就防住了（`fetch_prop` 会说"只被念到名字"），`patch` 这一头没有防。现在 `compile` 对着没有外观的名字直接跳过这一刀，两头的说法是同一句。护栏照旧钉住另外三条真用法：迟到的补画仍然落进那段**收掉的**窗口、画错了重画仍然落新格、填占位符仍然原地换掉那一格。

回执那一头：`move`/`draw`/`discard`/`recall`/`highlight`/`motion` 六个动词指一个不存在、或此刻不在台上的名字，全部回"成功"（实测 `moved vec-q to (900,400)`、`reused vec-o in 甲`，而道具表里只有 `vec-r`），只有 `camera` 有 `blindCamera` 那一句对账。后果正是 `blindCamera` 当初说的那一句：**模型把这份静默读成"动过了"**，接着往下排，整场建在一系列没发生的动作上。现在每一刀进门前先问台 —— 名字没落过笔、还是只被 `link` 念到过，两种说法分开；`discard`/`highlight`/`motion` 要的是**此刻站着**，`recall` 要的正是站着之外的（带上落过一帧就带得回来，那是它存在的全部理由）。`link` 是个例外：link 到一件还没建的东西本来就是替它登记身份，所以那一刀照落，但回执点名哪一头还没落过笔。问的是**带子尽头**那一刻而不是播放头 —— 这一刀是追加在尾巴上的，导演能落笔的台就是带头。

`link` 是这张表上唯一**没有时刻**的一格（只有 `to`/`relation`），所以倒带回到那一刀之前，导演的 `<stage>` 照样报 `links:resultant-of->b`，而 `b` 此刻还没上台。一次外观是一段窗口，一条 cue 是一段窗口，一条关系也是 —— 词汇里不该有第四种说法。`Link` 现在有 `at`，`agentSnapshot` 读的是 `l.at <= t` 那段前缀。顺带把上一件欠的一半补上：`visibleProps` 报的板名以前是 `p.scene`（道具最后被挪去了哪），而 `agentSnapshot` 上一件已经改成 `rev.scene`（站着那一次落在哪块板）—— 同一卷带子上一个名字两个板名，而这一份是要拿去画名单的。

时钟那一半：`owedAt` 里"这一拍落的笔"问过 `swept`（「换场扫走的那一格不欠时钟任何东西」），可**在飞的那两遍**没问 —— 它们只比 `rev.t` 落在不在这一拍的窗口里。于是一块被幕布压住的板上的空框仍然能让时钟停死，而观众已经不在那块板上。这一件给它补两条门（在飞的那一遍、后台那一遍各一条），外加一条"幕布还没盖过去确实该停住"的护栏守反方向 —— 上一件的变异测试露过这一处（把 `swept` 整句删掉当时一条都不红），所以这两条钉的是**时钟**而不是名单：观众已经不在那块板上，时钟却为一块他们再也看不见的空框停死在这一拍。

价钱还是同一句话的两笔：`audienceHas` 拿 `compiled.cues.find((c) => c.op === askedBy)` 找"这一刀落在哪一刻"，而镜头点名的东西观众看不见时它要**找不到**才说话 —— 找不到就是走完整个 cue 表。带子只增不改，这一问在排好的那一刻就该有答案：`Compiled.shotAt`（按 op 引用记，靠的是 `guard.revise` 那条"改不动就不换对象"的规矩，所以只有真被修过的那一刀才换了它的 `t`），问法整句搬到台上成了 `Stage.blindNames`，`loop.ts` 那一头只留一句转述。`⟲ 一拍` 那头每按一次把整张 cue 表 `filter` 一份新数组、`reverse`、再 `find` —— 占时钟的窄表（旁白与沉默）本来就在 `TapeIndex` 里，`t` 递增，所以 `prevSpokenStart` 是一次二分，而且 `t - c.t <= within` 只对最大那一格问一次就够（比它更早的离得更远，那条筛选本来也筛不住）。两处价钱各取三次最小值、同一台机器、128 001 条 cue 的带子（只留 8 格道具，所以差不是"台上有几个"）：点名一个空名字改前 **1.167 / 1.171 / 1.196ms** 一次，命中同一个数（**1.166 / 1.167 / 1.215** —— 那笔钱在 `find` 上，和找不找得到无关），改后 **0.001ms**；倒回上一拍改前 **13.192 / 13.220 / 13.234ms** 一次按下，改后 **0.0007ms**。建新表那一头没付钱：12000 拍每拍点一次名，改前 **37.0 / 37.4 / 37.5 / 38.1 / 38.8ms**、改后 **37.3 / 37.3 / 37.4 / 38.1 / 38.4ms**（各取九个样本最小值、交替五轮、同一台机器 —— 两档落在同一堆抖动里，所以那一格 Map 是免费的）。

`moment-receipts.test.ts` 钉这一节，整节在改前的代码上跑过一遍：**21 条里 15 条红**，其余 6 条改前就是绿的，它们是护栏（迟到的补画、画错重画、填占位符、`recall` 带得回撤下的东西、站着的东西照样点得动、`fetch_prop` 仍然报带子尽头 —— 导演档案那一头和镜头那一刻不许混成一个）。价钱那两条用 Proxy 数 cue 表上被走过的格子，并且先做**反向验**：同一张表上把改前那份读法问一次，`sweeps` 必须正好是 1，否则数出来的是探针自己。对账那两条照上一件的经验：刻点除了落笔与收笔，还要放**相邻边缘之间**的中点（`prop.scene` 在下一次落笔时才改，只问边缘正好错过"这一格还站着、而道具已经被后来的那一刀挪走了"的那一段），而且 `compared` 自己钉下限 —— 量不到东西的门不许绿。`camera-moment.test.ts` 那份"从头把带子再读一遍"的朴素参照跟着补了一句（`patch` 指一个没有外观的名字就跳过），那是照抄规则不是抄答案 —— 参照不跟着改，它自己就凭空造出一格满幅外观，两条对账当场红。

全套 202 → 223 条绿，原有断言仍然一条没改；tsc / build 干净，oxlint 仍是仓库里那两条旧警告。

`compile.test.ts` 用规模测试把这些钉住了：一条长带付一次线性的价钱，界内那一刀仍然算数（占位符排在镜头之前就得跟着镜头走）。

## 落下的那一格不许被后一笔改写

上面那一长串都在修"读法"，读的还是同一卷带子。这一件不一样：它修的是**落笔的几何**，因为带子只增不改那句契约一直在被破，而破它的正是最像地基的那一格 —— `compile` 每次都整卷重排。

`here` 落点要往后看（骨架先上占位符、后走那一刀的 pan，东西得落在走后的框里），这一头以前只认"下一句旁白"当边界。可 overlay 不占时钟，所以后落的那一批完全可以是**先镜头后旁白**，那一刀正好落在占位符的视线里：实测第一批 `{旁白, 占位符}` 落下的锚点是 `{x:700,…}`，追加第二批 `{往右一屏, 旁白}` 之后同一个道具成了 `{x:2300,…}` —— 观众亲眼看着一件导演没碰过的东西在台上飞走一屏，带子上没有任何一刀说要挪它。同一卷带子，一次排完和逐批排完给出两个答案，这比慢更糟：分享链接、重放、`⟲ 重排`全都建立在"同一卷带子只有一个台面"上。

修法是把往后的视线停在**批**的边界：`OpEntry.group`（`OpLog.append()` 每调一次发一批，一次工具调用排完的那一段就是一批，`stage_script` 一整份骨架正好是一批）。批内逐字不变，批与批之间是已经演过的历史，历史不许重演；`LOOKAHEAD_OPS` 那道封顶留着不动 —— 它管一批有多长，批的边界管读多少历史，两道墙各钉一条。缺 `group` 的带子（旧分享链接、测试里一次排完的 `tape(...)`）两边都是 `undefined`，于是整卷是一批，那一卷当年的排法一模一样 —— 门不许因为修了一格几何就把别人上的课改了；`restore()` 按最大号续上，因为"接着讲"接上去的现场，新落的那一批不许和档案里某一批同号。

`landed.test.ts` 钉三层，整节在改前的代码上跑过：**15 条里 6 条红**（形状 4、价钱 1、对账 1），其余 9 条是护栏。这里记一件手艺上的教训：对账那台生成器我第一版**每批都收尾于一句旁白**，于是它在改前的代码上是绿的 —— 批内那句旁白正好挡住往后的视线，跨批那一半根本没被读到，钉的是一条空街。真实的一批常常没有旁白：`paint()` 落的就是单独一刀 `build + here`，导演随后单独点一刀镜头（`director.ts` 每个动词一次 `append`），下一句常常要到再下一批才来。按真的动词重新分批改写生成器之后，对账当场在 `seed 2` 报出"落笔时 `x=1368`，追加之后 `x=1281`"。变异测试四处各红该红的那条：摘掉封顶 → 只红封顶那条护栏；摘掉批内那句"下一句挡住上一句" → 只红那一条语义；把边界做成"永远换批" → 红批内三条加封顶护栏；不落 `group` → 红跨批那三条。全套 228 → 243 条绿，原有断言仍然一条没改。

## 量过的墨不许每批重量一遍

上一件把往后的视线收回本批，于是**追加是安全的**：落一笔重排整卷，得到的台面和逐批排完一模一样。安全不等于便宜 —— 那一遍重排每格都要问一次"这幅画真正画到哪"，而这一问的价钱当年记在一本到 160 条就**整份抹掉**的账上（`ink.ts` 的 `measured`）。

于是记账那件东西自己变成了二次的。冷账上量同一卷带子排两遍（每格都是现画的、互不相同的画）：81 格 `81 / 0`、151 格 `151 / 0` —— 还没到那道 160，看起来没问题；201 格 `402 / 402`，再排那一遍 1243ms；401 格 `802 / 802`，2894ms。可导演不是一次交一整卷，他一批一批落笔，这本账因此一直是热的，那才是他真正付的价钱：同样这批画按每批 40 格连落七批，改前逐批是 `40 / 40 / 40 / 40 / 240 / 480 / 560`，合计 **1440 次解析** —— 前四批看着都对，到第 161 格那一批整份抹掉，此后每一批把前面全部重量一遍。**落一笔付的是全课的钱**，而这笔钱随课上画过的格数长，它恰好是"一堂好课"的形状。只交 `html` 的带子不过这个门，同规模一直是 1ms 量级 —— 这一笔账只在真画过东西的课上露头，所以它一直没被量到。

修法是把它换成有界的 LRU：命中就挪到最新那一头，越界从最久没人问的那一头**一条条**退，两条边界一道按条数（`MAX_ENTRIES = 4096`）一道按 keyed 标记的总字数（`MAX_CHARS = 8_000_000`）。字数那道才是真的：这本账多花的只是引用（字面量本来就在带子上）加一个几百字节的框，它防的是剪带之后 —— `cutFrom` 把带子剪断重排，那些画已经从带子上掉了，账还在替它们握着字符串。三条规矩各自有钉子：量不出墨的（`null`）照样入账，读不懂的画每批重解析一遍是最冤枉的那笔钱；比整份预算还长的画干脆不进账，存进去就是当场全部退出、连累别人；账上记的是**画布里的墨**，换算完的世界框在外面另算，所以同一幅画摆在两只大小不同的声明框里是同一个答案乘二，不是两次解析、也不是第二次拿着第一次的框。类带着预算导出：真要灌满 4096 条各不相同的画，光是解析就要十几秒，那一头量的是浏览器不是这一件，而"谁被挤出去、谁留在账上"这句话要在小预算上钉。

`ink.test.ts` 末尾两节钉这些，反向验证跑在改前的 `ink.ts` 上：那六条价钱里红的正是两条（冷账 `200 格`要 200、量到 400；逐批落笔要 280、量到 1440），其余四条本来就该绿 —— 它们是护栏（同一幅画占两格只解析一次、只交 `html` 的不过这道门、缓存不许改答案：逐刀比 `from`/`to` 而不是只比声明的 box、按标记缓存之所以是精确的）。带预算那一节走新导出的 `InkCache`，旧代码里没有这个名字，它钉的是退出的次序，本来就不必在旧代码上证明什么。变异测试九处各红该红的那条：命中不挪最新 → 红"问过就算最新"；越界整份抹掉 → 红那三条退出的次序；从最新那头退 → 同样红三条；`null` 不入账 → 红"读不懂的画也记账"；不记字数 → 红两条；超过预算也存 → 红"不如不存"那条（这一条第一版钉不住，因为那条"超长"的画其实没超预算 —— 探针自己先骗了我一次，改成长短两条对比才红）；把换算完的世界框记账 → 红"精确的"那条；干脆不记账 → 红八条；把 `MAX_ENTRIES` 改回当年那道 160 → 红两条价钱加那条护栏。量完：同一场戏合计 280 次（每格一生只付一次），冷账 401 格那一遍 2894ms → 7ms。全套 243 → 256 条绿，原有断言仍然一条没改。

还欠着的：`compile` 本身仍是每批整卷重排（`O(带子)`），只是这一件之后它不再顺手重解析每一幅画。批内视线已经收拢，把它做成增量的那条路现在是开的；同类的账还有 `log.ofTrack` 每批整份拷贝、`TapeIndex`/`StandingIndex` 每批重建（各约 0.5ms）、`App` 那边 `logRows` 的引用抖动。（下面"已经演过的那一截不许每批再演一遍"把前两笔 —— `compile` 与 `log.ofTrack` —— 做掉了，剩下那两笔现在是主要价钱。）

## 账本上的号也要过门

前面几件连着都在算"这笔钱谁付"，这一件不是 —— 它是一格**正确性**，而且破的正是"落下的那一格不许被后一笔改写"那纸契约：批的边界立起来之后，陌生人手里还剩一个办法把边界抹掉。门管了一个 op 自己说了什么（`guardOp`：坐标、时长、枚举、markup 的长度），却放着一个 op **坐在哪儿**几乎原样进门：`restore()` 当年整卷只查一句 `typeof e.seq === "number"`。这四个字段不是几何，是编号，而编号是拿去**发下一个号**的（`log.ts` 里那三行 reduce：`seq + 1`、`(group ?? -1) + 1`、`Math.max`）。JSON 里 `1e999` 是合法字面量、解析出来是 `Infinity`，而 `typeof Infinity === "number"` —— 恰好通过那句检查。

于是陌生人的五个字符能替整节课决定它怎么分批。走真实的那条路（地址栏 → `decodeTape` → `restore` → 导演接着讲）实测：档案里一个批号被灌成 Infinity，批号计数器就永远钉在 Infinity（`Infinity + 1` 还是 Infinity），"接着讲"新落的那一批于是和档案里那一批**同号**；同号就是同一批，`here` 的视线当场越过批的边界，读到身后已经演过的那一刀镜头 —— 落笔时锚点 `x=700`，追加一批 `{往右一屏, 旁白}` 之后成了 `x=2300`，两批之后 3900。观众亲眼看着一件导演没碰过的东西在台上飞走，而这次没有人落错笔，错的是一卷别人录的带子。

三种"看着是 number"的号各走一条路：`1e999` → `Infinity + 1 === Infinity`（钉死）；`1e300` → 有限、`Number.isInteger` 为真，而 `1e300 + 1 === 1e300`（同一个下场，而且躲得过"只要有限就行"那一版的修法）；`9007199254740991` → 2^53-1，`Number.isSafeInteger` 最大的那一个，而**它加一之后不再安全**，实测连着两次追加拿到同一个批号 `[…992, …992]`。所以门要的不是"这个号自己好不好"，是"还能不能从它往上数"：`MAX_LEDGER = 2 ** 40`（一万刀的课是 1e4，重排一千轮是 1e7 —— 离任何一堂课隔着三个数量级，离数坏隔着一万个）。`seq` 那一头是另一个形状：坏号进门以后 `lastSeq` 变 Infinity，此后每次追加都发同一个号，`entryAt` 查谁都是同几格，而学习者想剪回一段重排时 `cutFrom(0)` 一次删掉整节课（实测"删了 3 格剩 0 格"）。反过来 `seq: "3"` 这种**真读不出来**的号，改前被 `decodeTape` 的谓词整卷拒绝 —— 一节别人排过的课因为一格写坏了号而完全打不开，而门后来立的"坏字段被默认，不被整卷拒绝"一直没跟着改到这一头。还有撞号：两格都说"我在 seq 0"，`find` 取前面那格而 `answer` 用 `===` 找题卡，实测两张题卡加一句"答第一张"的回答，编译出来是 `[[0,"甲？",null],[0,"乙？","甲的答案"]]` —— 甲的答案被安到乙那张卡头上。

政策因此比 op 那一头更**笨**：一个号被"修正"成另一个号就是改写记录。认不出来的号只有两种诚实的下场 —— 这一格说不清自己在哪儿（`seq` 坏、撞号）就当没有落过笔；只是少了一个记号（`turn`、`track`、`group`）就退回这个字段的默认：`turn` 回 0（"这一格是第一轮落的"是一句关于槽位的话，不是改写一句回答），`track` 回一个记号 `*`（看得见"有这么一格"，演不到任何一堂课上；搬进 `main` 等于替陌生人决定他的课在哪儿演），`group` 回**没有这个字段** —— 因为"没写"本来就有一种真实的意思（旧链接整卷是一批），而把它写成 0 会替陌生人决定他当时是怎么一批一批落笔的。撞号时数组里在前面那一句算数，后面的当说不清；门不许在这儿重编任何号。`decodeTape` 因此不再逐格验收（它只认"是不是一卷带子"），验收在门口做，`App` 那句状态也改成报**进得来**的格数而不是地址里带着的格数。

`ledger.test.ts` 42 条，反向验证跑在改前的代码上：**33 条红**（批号三种、`seq` 三种、`turn`、`track`、撞号、坏号不再整卷拒绝、对账那一串 21 种毒），绿的 9 条全是护栏 —— 号可以比带子长（cut 过的带子本来就有洞）、批号允许跳号和倒序、旧链接不许补 0、乱序进来的带子按号排而号本身一个不动、分享一个回来回号不变、过门和没过门逐字同解、干净带子整格原样出去（identity，`compile` 拿 op 当 `shotAt` 的键）。变异测试十七处，红该红的：去掉上界 → 红 2^53-1 那条；`isSafeInteger` 换成 `isInteger` → **全绿**，这一处是等价变异（2^40 以内的整数本来就都是安全整数，上界那一句才是干活的），记在这里而不是藏起来；坏批号当作 0 → 红 4 条；坏 `seq` 也当作 0（不丢格）→ 全红；不守 `turn` → 红 5；坏 track 搬进 main → 红那条护栏；不查撞号 → 红 3；恢复整卷拒绝 → 红 8；不许 identity → 红那一条；门重做一格时把 `group` 弄丢 → **第一版全绿**，补一条"同一格里 turn 坏、group 好"才红（这是我自己漏掉的一种修过头）；`restore` 不排序 → 同样第一版全绿，补"乱序进来"那条才红；计数器从长度续而不是从最大号 → 红 9；门只管账本不管 op → 红原来那条"两条路都过同一道门"。全套 256 → 298 条绿，原有断言仍然一条没改。

## 已经演过的那一截不许每批再演一遍

上一件把账本上的号守住了，这一件回到价钱 —— 而且回到那一句被写了三次的话：**追加是安全的，不等于追加是便宜的**。`landed.test.ts` 那纸契约只是把往后的视线收回本批，`compile` 每一批仍然把整卷重新演一遍。

同一台机器、同一份探针、各取最小值（一批 20 轮、每轮三刀 —— `build` + `camera` + `narrate`，所以一批 60 格；这一件之前探针把规模写成"每批 20 刀"，那是批数乘轮数，不是格数，下面的数字全按格重量、按格说过一遍。96000 格那一档改前只跑得起一遍，192000 格那一档一次就是将近十分钟）：

| 带子 | 改前合计 | 改前落最后一批 | 改后合计 | 改后落最后一批 |
| --- | --- | --- | --- | --- |
| 12000 格（200 批） | 1183ms | 12.6ms | 112ms | 0.9ms |
| 24000 格（400 批） | 5885ms | 27.3ms | 465ms | 1.8ms |
| 48000 格（800 批） | 27127ms | 75.0ms | 2218ms | 5.9ms |
| 96000 格（1600 批） | 127974ms | 230.2ms | 14581ms | 22.3ms |
| 192000 格（3200 批） | **570 秒** | 336.6ms | 68.8 秒 | 39.2ms |

除 96000 那一档两头各只跑了一遍，每一档每一头都独立跑过一到五遍，两列各取最小值（所以同一行的两个数不一定来自同一遍）。抖动在一成上下：192000 格那一档改前三遍是 570 / 571 / 574 秒，改后两遍是 68.8 / 81.8 秒；12000 格改后五遍是 112 / 127 / 151 / 179 / 187ms。这张表要看的是两列之比，不是单个数。

只看解释器那一头（不经 `Stage`，所以不含仍然每批重建的 `TapeIndex`/`StandingIndex`）：192000 格逐批演完合计 **349ms**，落最后一批 **0.098ms**。也就是说改后剩下的那一截价钱已经不在"演带子"上了，它在"给带子建索引"上 —— 192000 格那一档 `new TapeIndex` 一次 16.4ms、`new StandingIndex` 一次 21.1ms（各取七次最小值），而"落最后一批 63.9ms"里就是这两笔加 `emit`。单次运行的抖动在一成上下（同一份探针 12000 格那一档重复三遍：112 / 127 / 187ms），所以这张表要看的是两列之比，不是单个数。

改法只有一句：解释器手上那些东西本来就是"走到这一刻的机器状态"，把它们从函数局部搬进一台活着的机器（`Interpreter`），带子往下长一截就只演那一截。`compile(entries)` 原样留着，它现在是"新机器演一遍"，所以所有旧测试走的路一个字没改；`perform(it, entries)` 是新的那一扇门。

能不能续，只问一句**引用**：`log.ofTrack` 给的是那一轨自己的数组，落一笔往里 push（引用不变 → 续演），剪带、载入、清空换的是数组（→ 从零演）。所以这一件把 `OpLog` 一并改成三本账（整卷 / 按轨道 / 按号）：`ofTrack` 从"每批现 `filter` 一份"变成把带子本身交出去，`asides()` 从"整卷 `map` 再 `Set` 再展开"变成按轨道读长度，`entryAt` 从线性扫变成一次查表。这三笔都是续排的前提而不是顺手的优化 —— **旧写法每批现造一份新数组，"读的还是不是那一卷"这一问根本没有答案可问**。反面也一样成立：`all()` 故意仍然返回拷贝，只有 `ofTrack` 需要带子本身；把 `all()` 也换成引用，`ledger.test.ts` 那一头拿它当记录改的调用方当场被类型抓住。`Stage` 按轨道各留一台机器（`machineMain` / `machineAside`），机器的生死完全由引用决定，所以这里不需要维护"哪一头换了带子"的清单 —— 换掉就是回收。

三处 O(带子) 的收尾各自换成跟着带子走，而它们正是三处会各自错法的地方，所以一条条和逐字抄下来的参照对账（`groundsAtEnd` + `unionBox`、"逐张问你在哪一拍"、"cue 表 reduce 一遍"）。两处不讲理的下场是参照教的：一块板上站的格子**全都量不出地方**时，旧写法给出的答案是"这块板有一屏那么大"而不是"这块板没有地皮"（分板那一步根本不看盒子，`unionBox` 才跳过它们），所以 `BoardGround` 除了四条边各一个堆，还得单独数一个"此刻站着几格"；撤空的一块板要整个从 `scenes` 里消失，那是另一头。第二处更险：拍只在旁白与 `beat` 上收口，所以 `quiz → camera → quiz` 一整段里两张卡都还开着 —— 若按"只留最后一拍的卡"去省，在开新一拍那一刻顺手清空 `openGates`，前一张卡就永远停在它落下那一刻。清空只许发生在**收口**那一刻，收尾那一截只给"end 还会长"的那一拍重账。

`incremental.test.ts` 16 条，分四层：形状（两百卷随机带子 × 三十批逐批对账，逐字段列到每格外观的窗口两端、每一刀 `from`/`to` 与**那一刀的引用**、卡的 `until`、拍的 `seqs`、时长、每板地皮、`shotAt`；参照不许用任何缓存）、价钱（Proxy 数**按下标读了几格**：回头读过的格子必须为 0，带子长四十倍而本批多读的格子一格不许多）、收尾三处（含上面那两个下场，外加"两拍三刀"那种绝对值断言）、护栏（一次排完一卷带子的答案不许因为换机器而变；旧链接没有分批号时那两个数仍然 2300 / 700；内容相同换了数组就得从零再演；`Stage` 那一头逐批 + 剪带 + 插播来回切）。

反向验证跑在改前的代码上，方法很笨也很管用：加一份 `perform` 的历史替身（每次调用就是整卷 `compile`，机器只记引用），测试正文一个字不改。结果 **14 绿 2 红** —— 绿的正是预期的：改前那一头"续排"和整卷重排是同一件事，所以形状层根本没有东西会错；红的两条是"落一批：回头读过的格子 = 0"（实测回头读过 212 格）和"换带子那一头从零再演"（旧 `ofTrack` 每批现拷一份，引用那一问当场没有答案）。这一节的**价钱**是那一头唯一能红的东西，而它红了 —— 这就是这一件该被钉住的那一层。

变异十七处，红该红的：摘掉堆的惰性删除 → 红"一板的地皮"加旧 `compile.test.ts` 那条"撤走的东西不许再把画面撑大"；`holds` 永真（剪带也不换机器）→ 红 5 条；`holds` 永假（永不续排）→ 红剪带那条、"同一卷带子反复问"那条、价钱那条，外加一条毫秒门；`duration` 不算尾巴 → 红新那条加旧"整场时长"那条；`closeBeat` 不把 end 交给卡 → 红 6 条；`held` 不数占不了地方的格子 → 红"一板的地皮"；`drop` 忘了摘 `held`、`empty` 永不成立 → 各红"一板的地皮"（前者连带毫秒门那条）；`ofTrack` 改回每批现拷 → 红"换带子那一头"；`perform` 干脆每次新机器 → 红 2 条；`played` 少记一格（每批多演一刀）→ 红 12 条；收尾改回全表重扫 → 红"收过口"那一条；收尾那一截把重账写成 `g.until = g.t`（等于没收） → 红"卡的窗口"那一条。

四处**第一版全绿**，记在这里而不是藏起来。两处是等价变异：`closeBeat` 之后再抹一次 `openGates`（已经空了，再抹一次不改变任何东西）；`BoardGround` 的记号从 `++` 改成 `+= 2`（它只是堆里配对用的键，跳号无所谓）。另外两处不是等价变异，是**我的测试当时钉不住**，都补了才红：把"顺手记最大值"写成"记最后一刀"在原来那卷带子上两种记法同一个答案（长的那一刀正好落在尾巴上）→ 补一条把 600 的强调夹在中间、后面只跟一刀 1ms 的镜头；收口时忘了清空 `openGates` 在原来那卷带子上也看不出差别（前后两拍的 end 恰好相等）→ 补一条"收过口的卡不许被后面那一拍的 end 回头改写"，两拍刻意不等长。这两处的教训同一句，而且比上一件那条更尖：**对账的参照和机器共用同一份收尾时，收尾自己错法就两边一起错，绿灯什么都没说** —— 那一层必须至少有一条不问参照、只按绝对值说话的断言。

全套 298 → 314 条绿（`incremental.test.ts` 16 条：形状 6、价钱 2、收尾三处 4、护栏 4），原有断言仍然一条没改；`offstage.test.ts` 只把一份参照的形参从 `OpEntry[]` 放宽成 `readonly OpEntry[]`（类型，不是断言）。tsc 干净，build 干净，oxlint 仍是仓库里那两条旧警告（App.tsx 的 ref-in-render）。

还欠着的，而且现在看得更清楚了：`TapeIndex`/`StandingIndex` 每批整本重建（192000 格上各 16–21ms，改后这一批的主要价钱就是它 —— 上一条表里那 63.9ms 落最后一批基本全是它加 `emit`）；`App` 那边 `logRows` 的引用抖动。`log.ofTrack` 与 `compile` 这两笔这一件做掉了。（下面"已经排好的那一截不许每批再排一遍"把 `TapeIndex` 那一半做掉了，`StandingIndex` 与 `logRows` 仍然是每批。）

## 已经排好的那一截不许每批再排一遍

上一件把解释器搬进一台活着的机器，剩下的价钱就明明白白落在两本索引上：`runtime.ts` 的 `recompile` 每批 `new TapeIndex` / `new StandingIndex` 各一次。同一台机器、同一份探针（一批 12 格：道具、镜头、旁白、强调、运动、换场、卡、撤下），每批落完就 `perform` + 建索引，各取最小值：

| 带子 | 改前合计 | 改前落最后一批 | 改后合计 | 改后落最后一批 |
| --- | --- | --- | --- | --- |
| 200 批 / 2400 格 | 35.7ms | 0.305ms | 16.8ms | 0.117ms |
| 400 批 / 4800 格 | 130.6ms | 0.603ms | 52.7ms | 0.219ms |
| 800 批 / 9600 格 | 565.0ms | 1.552ms | 244.5ms | 0.754ms |
| 1600 批 / 19200 格 | 2660.0ms | 3.535ms | 1339.4ms | 1.908ms |
| 3200 批 / 38400 格 | 12085.7ms | 8.611ms | 6546.0ms | 4.565ms |

改后**形状还是二次的**，这一件没有把它改成线性 —— 因为剩下的那一半是 `StandingIndex`：38400 格那一档落最后一批 4.565ms，而同一规模 `new StandingIndex` 一次就是 4.02ms（`new TapeIndex` 一次 3.00ms，那一笔这一件消掉了）。也就是说这一件把 `TapeIndex` 从"每批"做成"每卷一次"，下一件把同一句话搬到另一半上。抖动仍然在一成上下（同一份探针三遍：38400 格改后合计 6546 / 6588 / 6759ms），所以这张表要看的是两列之比。

改法只有一句：`Compiled` 里那两张表（`cues` / `gates`）本来就是机器手上会长大的容器，所以**认的东西换了、认的还是同一句引用** —— 解释器认那一轨的带子数组，索引认这两张容器。落一笔 → 同一批容器 → 只吸收新落的那一截（`grow`）；剪带、载入、清空 → 换的是整台机器 → 两张表都是新数组 → 从零建一本。门写成模块函数 `reindex(ix, compiled)`，和 `perform(it, entries)` 同形，`runtime.ts` 一条轨道一本。两处认错的代价不对称，所以 `holds` 两张都比：只认 `cues` 那一半的写法能把新 cue 表续到旧开卡表上，那一头是"哪张卡还没答"的账 —— 红的是护栏里"只换卡表也要重建"那一条。

三处不是"照抄一遍就完事"的地方：

1. 两条前缀最大值（`camMaxEnd`、`hlMaxEnd`）本来是局部变量，搬成字段游标（`camMax` / `hlMax`），续排从上一次那个数接着记。写成"记最后一条的 `end`"当场不是前缀最大值 —— 红旧 `frame.test.ts` 那两条（叠层那一条与新写的护栏那一条）。
2. 开卡表是这本索引上唯一会被**中间**改动的账：他的回答是身后的一刀 `answer`，把一张早就进过账的卡原地从"没答"改成"答过了"。所以它不许"只长尾巴"。换成惰性作废：新落的往表尾接，表头那一截答掉的问的时候逐条迈过去（`head`，迈过去的那一格永不回头问第二次），全表那一问筛掉作废的、**筛剩不到一半才换表**。第三条治的是"答在中间的那些"（`head` 迈不过去）；它不许写成"一发现有作废就整张换表"，那样每轮抄一次表、抄的还是整张表的长度 —— 这一处本次**量不到**（那一层省的是内部数组的拷贝，不是卡表上的读数），所以规矩写在注释里而不是断言里，这条诚实记在这儿。
3. `cue.to` 会被换场那一刀**原地改写**（`transition` 先落一条站着不动的 cue，再把落点写进同一条）。索引读的是 `t`/`end` 与对象引用，而这一改写发生在 `pushCue` 之后、本批尾巴被吸收之前，所以续排读到的一向是改完的那一份 —— 这条规矩得有人钉，否则下一件把它挪成"边走边记"就当场破了。护栏那一条还顺手钉住"`from` 与 `to` 必须不同"，否则它钉的是一条空街。

`index-tail.test.ts` 21 条，分四层：形状（一百卷随机带子 × 三十批逐批对账，每一问在全部刻点上比 —— 刻点含每格两端、两端之间、每刀换场的 `flip`；参照每批拿整卷带子从头再排一遍再新建一本，不许复用机器手上的容器；另有剪带、载入、插播三条"换台面必须从零建、接着落笔又走续排"）、价钱（两张容器各套一层 Proxy 数**读过哪几格**：回头读过的必须为 0，往前读的至多本批新落的那几格，且同一批尾巴落在 60 批与 2400 批（带子长四十倍）的两头上读过的格子数一格都不许多；答掉表头那两张那一问还钉住"问的时候只迈作废的那两格"与"迈过去的永不回头"）、开卡表（表头答掉要指到下一张、全答完就没有答案、压实不许挤掉还开着的、和整张卡表重筛一遍同解、**还没问出口的那一张不许被提前答出来**、表头开着而身后一串答光时 `cardAt` 不许让给答过的那一张）、护栏（一次建完与逐批续排逐刻同解；内容相同换了数组必须重建；只换卡表也必须重建；换场那一刀的原地改写；`Stage` 那一头逐批 + 剪带 + 插播来回切仍然与现建一本同解）。生成器仍然不许每批收尾于旁白，而且这里更严：**答一句也随机落在身后某一批里** —— 开卡表要的就是这种中间改动，答在头一批和答在最后一批是两种完全不同的错法。

反向验证跑在改前的代码上，办法和上一件一样笨：把 `reindex` 换成历史替身（每一批都是 `new TapeIndex`），测试正文一个字不改。结果 **16 绿 5 红**。绿的正是预期的：形状那一层改前"续排"和整本重建是同一件事，所以那一层根本没有东西会错；红的五全是价钱与那句引用 —— "落一批：回头读过的格子 = 0"（实测回头读过整张 cue 表）、"答掉表头那两张"、"答在表尾那一张"（那一头每批重筛整张卡表）、"换台面那一头从零建"和"认容器只认引用"（旧写法根本没有 `holds`，`reindex` 每批都返回新对象）。这一件的**价钱**是那一头唯一能红的东西，而它红了。

变异十五处，红该红的（后面是红的条数，跑在整套上，跨在旧测试上的也照记）：`holds` 永真（剪带也不换本）→ 6 条，含旧 `answer.test.ts` 那条"剪断到那一拍之后他的回答跟着回去"和 `incremental.test.ts` 那条"台上那口钟"；`holds` 永假（永不续排）→ 5 条（价钱那一节三条全红，加"换台面那一头从零建"与认引用那条护栏）；只认 `cues` 不认 `gates` → 1 条，正是新加的那条护栏；`freshHead` 不迈过去 → 6 条，含旧 `answer.test.ts` 那条"两张卡各归各的答"和 `compile.test.ts` 那条每题一答；压实之后 `head` 不归零 → 2 条；永不压实 → 2 条（新那条"堆成长尾"加旧那条每题一答）；卡表每批整张重筛 → 价钱那一节 3 条；cue 表每批从头吸收 → 1 条（"落一批：回头读过的格子 = 0"）；前缀最大写成"记最后一条的 `end`"两处各红 —— `camMax` 红旧 `frame.test.ts` 那两条（同一拍里两刀叠着来、索引与整条带子扫描同解），`hlMax` 红旧那条长寿叠层的护栏；游标每次 `grow` 从头重算 → 1 条，红形状那一百卷；`cardAt` 的 `<` 换成 `<=` → 2 条；`grow` 时清掉运动表 → 4 条。两处数字在两次跑之间差一条：那一条是 `compile.test.ts` 里的毫秒门，它在共享机器上本来就会飘，所以这一节不把任何结论记在它身上。

三处**第一版全绿**，记在这里而不是藏起来。一处是这一层量不到的：`openGateSeqs` 一发现有作废就整张换表 —— 那一头每一问抄一次表，抄的正是整张表的长度，可它省的是内部数组的拷贝而不是卡表上的读数，这一层的尺子量的是后者，所以认了：钉不住就是钉不住，规矩只能写在注释里。另两处不是等价变异，是**我的测试当时钉不住**，都补了才红：`absorbGates` 不分答没答全接进开卡表 —— 续排那一头新落的每张当时都没答，于是直播那条路上两种写法同一个读数，而 `load()` 那一头（一卷已经答过大半的课）第一问要从表头走到表尾，补一条"从零建一本之后第一问只读还开着的那几格"才红；`cardAt` 那个 `<` 写成 `<=` —— 第一版那卷带子上两种写法同一个答案（表头那张恰好落在"已经走过"那一段里），补一条"卡片落在中间那一拍之前、时钟站在它被问出来之前"才红。同一节里还有一条是我先写错了带子形状才量到东西：价钱层那问"答掉一张旧卡"我第一版按**每张都答完**的课写，那一头建表时 `openAt` 一张都不接、之后每一问都是空表，改前改后一样便宜 —— 换成一张都不答、只答表头那两格的课，那一笔税才露出来。教训还是上一件那一句：**对账的参照和机器共用同一个读法时，参照自己错法就两边一起错，绿灯什么都没说** —— 所以价钱层一条都不问参照，只按绝对值说话。

## 公式是排版的，不是手画的

道具 markup 里任何带 `class="tex"` 的元素，它的文本内容会被 KaTeX 排成 **MathML**，浏览器自己完成排版。契约就一条：给一个 `<text>` 挂上 `class="tex"`，内容写 LaTeX（`<text class="tex" x="40" y="90" font-size="48" fill="#fde68a">\vec r=\vec a+\vec b</text>`）—— `y` 是基线，窗口的位置和宽高由舞台算。模型自己写的 `<foreignObject>` 不算入口：DOMPurify 把它列进 svg 禁用表（那是 mutation-XSS 的门），净化器会把这扇窗连同里面的公式一起删掉，所以只有 `class="tex"` 这一条路。

只取 `output: 'mathml'`：不引 KaTeX 的 CSS，不搬它的 woff2，不改写任何 `url()`。日志里存的仍是那串 LaTeX 源码 —— 所以公式进得了分享链接、重放和重排，而且它跟着画面一起被特写放大，和一条笔画同样缩放。

代价：MathML 的渲染细节由浏览器决定（Chrome/Safari/Firefox 原生，旧浏览器会退化成一行普通文本）。这是换来的：真分数、根号、下标、矩阵，零样式注入。

## 哪些轮子是借的，哪些是自己造的

借的：`@earendil-works/pi-ai`（模型传输、流式、凭据、faux provider）、`three`（3D 图形栈）、浏览器自己的 SVG/HTML/CSS 引擎（2D 表达面就是标准 DOM，没有再包一层）、`speechSynthesis`（配音）、`katex`（只做 LaTeX→MathML 的字符串转换，排版交给浏览器，见上）。

自己造的只有三样，且都有理由：**op 日志 + 解释器**（没有任何库把"只增不删的指令带"当唯一真相，从而让分享、重放、重排都是副产品）；**时钟归旁白**（GSAP / Motion Canvas 这类 tween 库要夺走时间的所有权，而这里 `t` 必须是纯函数，倒带和分享才可能字节一致）；**二维板 + 摄影机**（Pixi/Konva 这类保留模式画布吃的是解析好的图元，接不住"模型边吐 markup 边长出来"的磁带头，也没有 shadow root 的作用域隔离）。

结论：表达层没有重造轮子 —— 它就是 DOM；重造的是**时间的所有权**，那是这个产品区别于"一段渲染好的视频"的地方。

## 验证分三层

别拿 fixture 的绿灯当服务商链路的绿灯。

1. **排练模式（faux）**：只证明"我自己的代码自洽"。
2. **mock OpenAI 兼容服务**（`scripts/mock-openai.mjs`，自己的 Node 进程）：验传输适配器形状。开关：`MOCK_PORT`、`MOCK_HOLD=<ms>`（拖住首拍以量冷启动窗口）、`MOCK_429=<role>:<N>`（该角色前 N 次返回真 HTTP 429）、话题里写 `MOCK-TRUNC-N`（前 N 次导演调用只回 reasoning + `finish_reason=length`）。计数器是进程全局的，换场景要重启 mock。
3. **真实服务商**：端到端跑完整堂课才算证。

双端对账是唯一免疫观察通道污染的办法：mock 的 stdout 记"发出了几条什么形状"，页面 transcript 记"收到几条 / 推了几条 nudge"，两边对上才算。

服务商限流通常是 **tokens-per-minute**：单场长课能吃到十几万 tokens。测完一轮要算代价，别为验证反复开真课。

## 已知边界

- 密钥在 localStorage，DevTools 可见（见上）。
- 3D 的拖动角度不进分享链接（设计决定：那是学习者状态，不是演出）。
- `build` 的 `here`（"落在当前镜头正中"）由 `compile.test.ts` 钉住了语义（同帧让位、跟着本拍的 pan 走、命名别的板就落到那块板的地皮上），由 `landed.test.ts` 钉住了它的边界（往后只读到本批为止，追加的那一批不许改写已经落下的一格），但真机上仍只有 mock/faux 触发过 —— 真实模型每次都自己报了坐标。
- `inkBox` 只测平移和缩放两种变换，遇到 rotate/skew 就明说"这 estimate 不可信"并退回声明的 box —— 宁可瞄框，不瞄一个算错的墨迹位置。
- 量墨这本账按**标记**记，不按格子记，也不带预算以外的失效：`patch` 换一幅画就是换一段字面量，所以不需要谁去清它；被剪掉的那些画由字数那道边界挤出去。真正会重复交同一幅画的场景（同一句 `svg` 抄进两格）因此只付一次，这是有意的 —— 它量的是 markup，不是那一格。
- 仓库里留了几条**毫秒**门（`compile.test.ts` 的"一板的地皮测一遍就够了"、`camera-moment.test.ts` 的倍率 <12），它们只在机器空着时准：全套并行跑时基线 HEAD 自己也会红一次（实测六轮里一轮）。行为与格子的门才是可依赖的那一层，毫秒那几行是兜底，不是判据。
- `guardOp` 兜解释器会算错的**量**（数字、枚举、时长、坐标、字符串与 markup 的长度、数量上限），不兜整卷的总量：每帧的可见道具数、DOM 节点数不在门上封顶 —— 那要封顶得先决定"一堂课能有多少道具"，那是编课的问题。它也不判断语义：一段把三板堆在同一个坐标上的带照样能过门。
- 账本那一道（`guardEntry`）的政策比 op 那一头**笨**，这是有意的：号不许重编，所以认不出来的 `seq` 和撞上别人号的那一格是**丢掉**，不是补一个 —— 丢一格比把整卷挪到隔壁那一格轻。两个后果写在这里：陌生人的带子里那一格从此不在（`#s=` 载入的状态条报的是进得来那几格，不是链接声称的格数），还有 `track` 认不出来时给的是 `"*"` 而非 `main` —— 那一句会排在台上、参与编译，但没有任何轨道演它，学习者看得见它站在那里而听不见它。宁可少演一句，不许把别人的一句挪进你正在听的那条轨道。
